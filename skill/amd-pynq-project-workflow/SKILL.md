# AMD / PYNQ 项目制作全流程

把需求、物理装置、软硬件实现、验证证据和交付包接成一条可复现的链路。依据此次小车制作记录提炼，通用方法可以迁移，板卡管脚、协议格式、参数和当前完成状态必须从目标项目重新确认。

## 开始工作

1. 判断用户要执行、诊断、审查还是发散方案，只推进本次方向；先读目标项目的 AGENTS、阅读入口、当前契约和最新构建记录。
2. 确认项目根目录、目标板及修订版、工具链、权威源码、候选版本、当前硬件连接和任务完成判据。已有项目优先沿用目录与脚本；陌生项目先建立最小事实表。
3. 将事实分为已实现、已验证、待验证；区分软件测试、生产 RTL 仿真、模块综合、整机布线、实板分项、实物联合测试。记录验证针对的源码身份和时间。
4. 本项目定位和历史证据看 [项目索引](references/project-map.md)；切勿把其中 2026-10-01 的快照当成永久最新状态。先查实时文件，处理文档与机器证据的冲突。

## 必须保留的工程不变量

- 数据、有效位、时间戳和序号属于同一批；采样新鲜度、驾驶意图租约和反馈年龄独立，发送心跳不能刷新采样或意图。恢复不能重放缓存运动。
- 单一权威接口源；寄存器生成文件不手改。改变布局或语义时同步升级版本、全部消费者、回归、HWH 和部署包；旧版本显式拒绝或隔离兼容。
- 控制和显示单向隔离；历史视频状态不参与当前控制。界面显示实际执行器反馈，不能用请求值或 PL STOP 代替 STM32 LOCK。
- 本小车生产架构为一个公共时基、一个 AXI-Lite 地址空间、一次全局快照和一个 MMIO 所有者；迁移时保留语义一致性，不强迫其他架构照搬模块数量。
- 电平、针脚、轮轴 CPR、标定、制动参数和物理延迟需要实物证据；名义值与仿真刺激不升级为实测。SCALE=0 的未标定状态不能为方便演示而默认填值。
- 生产核接入、完全布线和 bit/HWH 匹配需要各自证据。离线候选、Overlay、SD 系统镜像和允许运动的发布版本分别说明。
- 本项目当前 LAB_ONLY 包只支持电机断开的台架验证；本 skill 不改变其运动和发布门禁。硬件缺失时继续准备、仿真和记录待测项。

## 工作量与完成判定

以依赖和风险决定顺序：先打通最小跨层链路，补齐主功能，再优化；保护硬件标定与联合验收窗口。只有接口确实独立的任务才适合并行，使用者另有明确授权时再委派其他代理。模型费用或 token 数不作为验收标准。

改动后先运行受影响的有意义回归；接口/算术/流水变化补边界、批次配对及相应时序检查。到新候选里程碑执行完整流水线，避免每次说明文字编辑都重跑整机。审查先找可重复反例，再修复，最后独立复验；无新变化或未闭合问题时结束重复审查。

已有本项目可使用只读工具：

```powershell
python skill/amd-pynq-project-workflow/scripts/inspect_release.py --project-root .
python skill/amd-pynq-project-workflow/scripts/inspect_candidate.py --project-root .
```

`inspect_release.py`核对当前发布清单、候选、源码补丁、运行包、ZIP、固件、bit/HWH及实物证据；`inspect_candidate.py`核对不可变候选本身。两者都不加载 FPGA、不打开串口、不修改工程；结果仅为文件一致性，不是 HWH 语义、时序或实板验收。更完整的验证沿用项目现有入口。

交接只写本次结果、证据位置、剩余事项和下一步触发条件。技能覆盖全过程不意味着每次调用都执行全过程；不为沉淀技能扩展用户任务。
