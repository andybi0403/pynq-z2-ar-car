# 验证、优化、构建与竞赛交付

## 证据分层

| 层级 | 能证明 | 不能替代 |
|---|---|---|
| 软件参考/单测 | 算法、格式、边界、版本和生命周期的规定行为 | RTL或物理时序 |
| 生产C/RTL跨层回归 | 真实消费者和生产核在刺激/模型中的结果 | 实际UART、电气和电机 |
| 模块OOC综合 | 模块映射、资源和估计时序 | 整机CDC/I/O/布局布线 |
| 整机完全布线+HWH | 生产连接、约束下时序/DRC、地址/时钟/复位结构 | 板端驱动、色序和物理稳定性 |
| 实板分项 | 实际接线/电平/接口的测量结果 | 整机同会话持续运行 |
| 联合实测 | 固定版本/配置下完整链路和持续运行 | 未测场景或普遍保证 |

证据含实际执行命令、退出码、输入条件、版本/哈希、时长/次数和原始日志。FAIL/FATAL/ERROR优先于PASS字符串；超时必须失败。日志需说明证据是哪一层，软件fixture不得标hardware=true。

## 有效测试与审查

先用独立公式/参考或实际生产C判定预期，断言确切值、符号、边界和状态迁移。覆盖阈值前/等于/后、真实回绕、AW/W错开、WSTRB=0、真实背压、同拍更新、首次/反转/非法沿、来源停更新但发送线程仍活着、重启不重放。

选有价值的变异验证测试能抓到错误，例如删版本检查、删epoch复核、用PS时间替PL时间、插入额外合法校验字段、快照漏锁一组。先确认反例走到目标分支；存活变异是观察，分析是测试缺口还是语义等价。审查工具本身的错误和产品错误分开登记。

审查以风险和新变化为界，优先P0/P1与剩余系统缺口，不按固定轮次/巨量token任务机械执行。已有问题独立复验关闭后，不重复消耗整机回归，除非新改动、失败或证据不新鲜。任务结束仍交接真实未完成项。

## 时序与DRC优化

从实际路径/网表和当前厂商文档定位原因，记录功能与时序基线。时序报告检查setup/hold、失败端点、无时钟/无约束端点、CDC、reset、bus skew和板级I/O覆盖；WNS正值不覆盖未约束路径。管脚/I/O实际外部延迟未知时保留限制，不凭模板补值。

本案例经验：视频HP互连换SmartConnect并核对统一时钟/复位后，目标RAM异步控制警告消失；DSP乘法添加真实输入/乘积/输出流水并验证等价和批次后，17条流水建议消失。不要改规则严重级别、添加waiver或修改供应商RAM模式来做数字归零。

报告限定范围：最终v0.9整机WNS +0.077ns，不能沿用前一优化候选+0.745ns；DRC零Warning不表示全部日志零warning。REQP-181 Advisory保留原因与尚未实测边界，PS/DDR preset消息也单独说明。新查官方技术细节时验证版本，不依赖记忆或旧文档断言。

## 一次同源构建

本项目从根目录运行：

```powershell
python pynq_fpga/fpga/registers/generate_register_map.py --check
powershell -NoProfile -ExecutionPolicy Bypass -File pynq_fpga/preintegration/build_complete.ps1
```

先按当前`COMPLETE_BUILD.md`核对入口与依赖。完整流水线捕获源码→权威C/PC/主机/故障/RTL/像素/模块综合回归→来源核对→独立整机综合/完全布线→时序/DRC/HWH→bit/HWH/运行软件包→最终来源核对。每次用新目录，已有输出拒绝覆盖；失败不更新latest_candidate。临时反例、旧日志和历史基线与候选隔离。

仅修改主机软件或STM32固件时，可以不重跑bit构建，但必须另建发布清单，复用候选的bit/HWH哈希，列出候选之后发生变化的全部源码和测试，并重新绑定固件及运行文件。先用`inspect_release.py`检查这一补丁链，不能用改变候选历史记录的方式掩盖漂移。

来源包含RTL、机器契约/生成器、约束/板文件/IP、构建脚本、主机和权威STM32/PC输入；实际交付运行文件另绑定哈希。ZIP内文件也逐项重算，文件名/时间/硬编码ID不足以证明一致。完整路径副本移到新机器后须明确迁移路径和验证来源，不能默默将旧候选改成新版本。

本项目当前交付入口为`release_manifest.json`：`r2`保留完整PL构建身份，`r3`记录复用同一bit/HWH的软件/MCU修复、实板证据和运行包。查看状态时同时看候选的`hardware=PENDING`与发布的锁车实板范围，不能把前者误读为没有实板结果，也不能把后者扩张为整车release。

仅说明文档更新可以保留已核验bit/HWH并按现有流程重新打包，记录文档阶段和最终ZIP哈希；不能说重新测了RTL。运行代码、契约或构建输入变更必须新候选。Vivado命令的全局选项放在`-tclargs`之前，工具失败以退出码和阶段记录传播。

## 无电机实板验收

以当前`13_下一步上板与联合验收流程_20260930.md`和包内README为操作权威，设备/IP用实际检查值，不从案例猜。

1. 电机动力线物理断开；核对板卡、供电、电平、线束，再启动系统/网络。
2. 复制完整同版Overlay包，运行`deployment_check.py --board`、`lab_acceptance.py contract`。该检查不加载FPGA，Python要求与板端现状冲突时先解决兼容。
3. 加载/MMIO版本与快照→传感器正常/故障→UART STOP与新锁存反馈，保留独立场景原始记录。
4. 手转/滚动双轮实测CPR/方向/距离，保存实测标定，写配置后读回。
5. 色条→摄像头→OSD/身份/帧率；屏幕照片证明色序，提交时间证明软件事件，两者分开。
6. 同会话30秒试跑；摄像头/串口/线程等故障另开新场景，确认资源回收再重启。
7. 恢复正常条件，以固定实测配置另开1800秒会话，再由`joint_evidence.py`独立审核包/配置来源与原始日志。

30秒不能冒充1800秒；故障注入与正常稳定性日志不删段合并。启动就绪失败不开始正式计时；清理超时判失败且继续请求停止/关闭UART，不当资源已释放。脚本中的`--motor-disconnected`只是声明，不能替代真实确认。当前LAB_ONLY不提供非零驾驶/PREL；物理制动和运动release另行设计验收。

## 指标与对照

每行指标至少含名称、类别、值、单位、测量条件、次数/时长、原始证据。补上软件/实板层级、测量起终点、时钟映射/不确定度、源码/候选和标定身份。报告P50/P95/P99/最大值及样本量；统计方法固定并可重算，不只报平均。

预定义任务成功/失败/人工干预和有效总次数。性能记录包含视频持续吞吐/丢帧/CPU、控制周期抖动/截止期未命中、UART RTT/错误/超时、传感器误差/标定、LUT/FF/BRAM/DSP和时序。物理响应终点需仪器测量，串口发出STOP不是车轮已停；解码接收→SOF不是曝光→屏幕。

对照PL测速/OSD与软件实现时保持输入/输出、精度、分辨率/帧率、缓存/拷贝和系统配置一致，解释性能差异及适用条件。当前没有这组实板对照数据，不能承诺PL必然更快、得分或不可替代。

## 比赛导出与技能维护

按实际赛道核对交付：架构/数据流、接口、源代码、可重建脚本、工程/产物、环境、硬件BOM/接线/PCB/CAD、指标表/原始日志/脚本/波形、设计报告/演示视频、AI协作和自纠轨迹、技能包。来源登记逐文件/资源含上游commit、许可、采用方式、改动和验证；引用、移植、改造和独立实现分开，字体不沿用仓库主许可。

导出副本可按AMD推荐英文路径组织，写迁移表并从副本复现，保留权威中文工程。校赛暂不要求的材料不自动扩大当前任务；全国赛是否满足Ryzen AI PC等平台要求另核验。

技能验证看陌生队伍是否能找到输入、照方法执行、判断结果和知道何时停。流程建议需在后续实际使用中验证，跨板/题目复用前不能声称通用效果。新的失败形成稳定结论后再更新对应一条，避免积累无界“必须”。
