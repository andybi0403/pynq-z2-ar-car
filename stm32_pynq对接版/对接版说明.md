## 1. 本版的角色划分（对照 codex《BST-4WD改装说明》第 10 节逐条落实）

| 改装说明要求 | 本版落实 |
|---|---|
| 1. 保留电机底层（GPIO+TIM4 PWM+短路制动） | 原样保留，`motors()/brake()/channel()` 未动 |
| 2. USART2、9600 8N1 起步 | 保留，联调通过后双侧升 115200 |
| 3. 上电/复位后立即锁车 | `safe_init`：latched=1, FAULT_START |
| 4. 删除巡线/红外/寻光/灰度/RGB/风扇/舵机初始化 | **红外 GPIO（PA6/PA4）、云台舵机（TIM1/PA11）全部删除** |
| 5. 删除 STM32 超声波测量 | EXTI12/TIM2/Trig-Echo 全部删除，`EXTI15_10` 向量表条目移除 |
| 6. 接收 PYNQ 的左右驱动、运行许可、风险状态 | `$P` 帧（左右轮 PWM+距离+有效性+红外位图）、`$PSTOP#/$PREL#` |
| 7. 约 100ms 无有效帧独立停车 | 运动租约 250ms（≈2.5 帧）+ 数据年龄 200ms（≈2 帧）双保险；宽松于字面 100ms 的原因是 PYNQ Linux 调度抖动与 9600bps 帧传输时间（27 字节≈28ms），两项保证任一通道静默都在 250ms 内停车 |
| 8. 帧错误/任一板复位/传感器故障停车 | FAULT_FRAME 锁存；PYNQ 复位→$P 停→200ms FAULT_SENSOR；V=0 即锁 |
| 9. 故障不自动恢复运动 | 锁存语义不变，解锁必须 $PREL#/停止帧+条件持续 300ms |
| 10. 协议升级 | 已含逐字段格式校验+ASCII 和校验+序号位 |

## 2. 传感器迁移后的数据流

```text
超声波 Trig/Echo ──Pmod B 7/8──→ PYNQ PL 测距 ─┐
红外左/右 ──────→ PYNQ PL GPIO  ─┤              │
编码器 A/B ─────→ PYNQ PL 测速  ─┤→ PL 风险状态机→ PS 组帧
                                              ↓
                    $P,<L>,<R>,<V>,<MMM>,<IR>,<N>,<C>#  100ms
                                              ↓ USART2 (K1 插座)
STM32：解析→安全复检（近障回差/红外锁存/租约/数据年龄）→ TB6612 → 电机
STM32：$CAR,<L>,<R>,<LOCK>,<FAULT>,<MM>,<IR>,<DROP>#  300ms 回传 PYNQ
```

- STM32 不再测量任何传感器；距离、有效性、红外位图都是 PYNQ 上报值。
- STM32 保留的**独立安全兜底**：上电锁车、$P 帧校验、V=0 锁车、数据 200ms 过期、租约 250ms、近障 200/250mm 回差（只清正向分量）、红外置位锁存、看门狗 0.5s。PYNQ 崩溃/误发/断线时底盘仍会停。

## 3. 与演示版的协议差异

| 项 | 演示版 | 对接版（本版） |
|---|---|---|
| $P 帧格式 | `$P,L,R,V,MMM,N,C#`（最长 27） | `$P,L,R,V,MMM,IR,N,C#`（最长 29） |
| IR 字段 | 无（红外在 STM32 本地读取） | 0..3，bit0 左 bit1 右，1=障碍，**来自 PYNQ** |
| 红外锁存 | 本地 GPIO 触发 | $P 帧 IR≠0 触发，语义相同（锁存、需解锁） |
| $ARM#（USB） | 可解锁驾驶（本地传感器有效） | **无法解锁**（控制源切换会立即废弃旧 `$P` 快照与解锁计时；USB 控制期间 `$P` 也被忽略）——本版 USB 口只用于 `$HALT/$IDLE` 停车与诊断读数 |
| 蓝牙模式 | 可用（超声波接线在 STM32 时） | 仅限台架短测：数据只能来自 $P 帧，无 $P 时 200ms 后必锁 |

PYNQ 侧统一用 `pc/pynq_link.py`：`CarLink(port, proto='pynq')` 发对接版帧，`proto='demo'` 发演示版帧；两种帧的校验和均已和固件单元测试帧逐字节核对一致。

## 4. 本版验证记录（2026-09-17）

1. 主机单元测试（MSVC，`tests/run_tests.cmd`）：通过。覆盖上电锁、IR 来自帧、RAW 驱动、近障回差、V=0、200/250ms 双保险、校验和拒绝、字段破坏、±2400/9999 极值、uint32 回绕、旧帧路径。
2. **模糊测试（ctypes 加载 DLL）**：全部通过——
   - 30000 条随机合法帧：全部接受，left_req/right_req/ir/distance_mm/valid 与输入一致；
   - 30000 次单字符破坏：**全部拒绝**（校验和覆盖 '$'..'N' 的性质，任何破坏必错）；
   - 全长度截断/加长：全部拒绝；
   - ±2400/0/9999/IR 全组合极值枚举：接受且数值正确；
   - 50000 段随机垃圾：无崩溃、未解锁状态绝无运动输出；
   - 超限 PWM（±99999）：钳位到 ±2400，不拒绝（宽容限幅语义）。
3. 模糊测试发现并修复的真缺陷：**帧长上限 28 少算 1**——双负 4 位 PWM+4 位距离的最长帧实为 29 字符（`$P,-1502,-1751,0,6248,0,1,D1#`），原上限会把这类合法帧拒为坏帧（故障锁车）。已改为 29（演示版同步 26→27）。
4. 行为审查修复：`safe_pframe` 开头不再用旧快照 tick——$P 帧是对接版唯一传感器来源，帧间隔内数据必然"老化"，先检查会把正常新帧误判过期而错误锁车；改为**先更新数据后检查**（`safe_frame` 旧路径无此问题，本地传感器 60ms 刷新，保持原逻辑）。演示版同步修复并重编译（8792 字节）。
5. **"没反应"陷阱修复（两版同步）**：USB 诊断口接管后原设计永不自动释放，PC 调试拔线后 USART2（PYNQ/蓝牙）的字节会被中断直接丢弃且无本地自救手段（$BT# 只能从 USB 发），小车表现为永久无反应。新增：接管且处于停止状态、1000ms 无任何 USB 字节 → 自动交还 USART2；交还动作本身锁车，新控制源必须重新解锁，不会产生意外运动。USB 行驶中拔线的链条：租约超时锁车 → 1s 后释放，同样完整。
6. 逐项复核确认无误：PWM 极性与原车一致（TIM4 CH1=PB6 右、CH2=PB7 左，10kHz）；SWJ_JTAGDisable 的必要性（PB4 右电机方向脚默认是 NJTRST 功能，不 remap 则右轮失效）；IWDG 实际 624ms 与主循环无阻塞匹配；接管首字节保留边界逻辑；演示版固件收到对接版 $P 帧时校验和必错 → FAULT_FRAME 锁车（安全方向失败）；环形缓冲与串口带宽余量充足。
5. `-Wall -Wextra -Werror` 零警告；静态RAM data+bss=3272/20480（另需预留栈/堆）。

## 5. 尚未覆盖（须上板/联调确认）

### 5.1 USB 自动释放的可审计验证记录（主机侧推演，待上板复核）

`usb_byte_ms` 仅由 USB ISR 在读到任何字节（含错误字节）时刷新，释放判断 `command==STOP && millis-usb_byte_ms>=1000` 的五个场景推演：

| 场景 | 行为 | 结论 |
|---|---|---|
| 开机>1s 后 USB 首次接管 | 首字节即刷新 usb_byte_ms，接管瞬间不可能误释放 | 通过 |
| USB 持续残帧/未知字节 | 每字节都刷新 usb_byte_ms，不会误判空闲 | 通过（修复 A-03） |
| USB 有效控制帧行驶中 | 帧刷新 usb_byte_ms；拔线后 command≠STOP，释放被 STOP 门控挡住，随后运动租约锁车 | 通过 |
| 停止状态拔线 | 1000ms 无字节 → release_to_usart2() → 内部 safe_fault 锁车，PYNQ 需重新走解锁 | 通过 |
| USB 与 PYNQ 同时接线 | USB 任何字节都会接管并锁车；PYNQ 帧在接管期间被丢弃 | 符合独占设计 |

上板复核方法：逻辑分析仪/串口助手分别注入残帧与完整帧，观察 1s 后控制权归属（$CAR 的 LOCK 位与 FAULT 位）。
