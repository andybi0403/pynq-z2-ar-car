# 构建部署与接手步骤

## 文件与环境

权威目录：stm32_pynq对接版（应用源码/启动/链接/构建/ARM 测试）、pynq_fpga（RTL/契约/PS/完整打包/测试）、tools/car_receiver（桌面完整控制台）、work（本机脚本与证据）。stm32预备程序和历史 release 用于追溯。

电脑需要 Python 3.10+、pyserial、paramiko；ARM 测试另需 unicorn、pyelftools；界面测试需 Node/Playwright。STM32 使用 CubeIDE 自带 arm-none-eabi GCC，板级完整 FPGA 构建沿用 Vivado 2026.1；PYNQ 沿用现有系统/环境，先记录真实 Python/PYNQ 版本，不为演示重装系统。

```powershell
python -m pip install pyserial paramiko unicorn pyelftools
powershell -NoProfile -ExecutionPolicy Bypass -File "stm32_pynq对接版/build_safe.ps1"
python -m unittest discover -s "stm32_pynq对接版/tests" -p test_uart_roles_arm.py
python pynq_fpga/fpga/registers/generate_register_map.py --check
python -m unittest discover -s pynq_fpga/host/tests -p "test_*.py"
python -m unittest discover -s pynq_fpga/preintegration/tests -p "test_*.py"
python tools/open_car_console.py
```

ARM 回归依赖已构建的 build_safe/safe_car.elf；不要拿过期 ELF 验证新源码。完整 FPGA 构建入口见 pynq_fpga/preintegration/COMPLETE_BUILD.md 与 build_complete.ps1。只有修改 RTL/约束/接口才需重新布局布线；纯交接文档不重跑整机。

## 烧录与查询

r17b 已成功烧录，本次交接无需重复擦写。成功流程及全片备份在 work/uart_regression_audit_20261026/ch340_flash_20261026_200849_440206。

今后确需烧录时：先读 flash_recovery_ch340.py；不加参数仅核验本地身份，不开硬件；硬件参数必须按脚本 argparse 和真实状态填写。该脚本绑定旧 r16 全片身份，不能当作允许任意固件覆盖的通用下载器；重复烧录若身份不符合应停止并保留证据。

历史成功下载为 COM10、S5 ON、BOOT0=1 复位后首字节 0x7F；恢复正常应用为 BOOT0=0 并复位。电机动力本轮保持连接，这是用户确认状态，不得在日志中伪填“已断动力”。工具不发 GO、R1 或 D1。

## PYNQ 部署（接手后执行，当前尚未执行 r17b 部署）

1. 保持当前控制服务停止、锁车状态，备份原目录/服务配置。COM14 为 PYNQ USB 调试管理口，COM10 是电脑到 STM32 扩展板串口，不能混用。
2. 核验 r17b ZIP SHA256（见版本表），通过本地网络 scp/SFTP 或 tools/car_usb_transfer.py 的确认传输上传到 /home/xilinx/；不要执行 tools/car_deploy_console.py 中写死 r12 的历史部署。
3. 解压为 /home/xilinx/v011_uart_recovery_20261026_r17b；先读包内 README_UART_RECOVERY.md、SENSOR_CONSOLE_GUIDE.md、两个 manifest 和 start_console.sh。
4. 根据包内步骤构建 native 库并核验 deployment_check.py、HWH 契约、console_manifest 中的文件哈希。不要复制来源不明的旧 .so；仅在源代码哈希相同且 ABI 环境相同的情况下复用。
5. 先恢复只查询的 STM32 通信，再以真实电机供电状态启动完整控制台。包中默认观察/锁车，禁止用“disconnected”环境变量伪报动力已断以绕过门禁。
6. 检查实际 LOCK/PWM、新鲜度、视频、状态 URL 和关闭流程；实测标定后才进行真实操控与演示验收。

桌面可直接打开 r17b/desktop/打开完整控制台.pyw，或 tools/open_car_console.py。本地完整界面可离线打开；连接助手由用户触发才联网。浏览器本地显示不证明板端服务启动，更不证明串口通。

重启后若无路由导致地址发现 ENETUNREACH，需修复/验证运行时地址发现并获取真实服务 URL，不要把 token 粘到公开截图或 GitHub。默认账户示例不是生产凭据；交接不保存私人密码。

## 归档恢复与完整性

运行 `python handoff/20261026/verify_handoff.py` 核验归档分片和运行包。加 `--extract 日志恢复目录` 后将分片顺序拼接在该目录、校验完整 ZIP 并解压，恢复原 work/、tmp/、构建证据等路径。恢复目录应为空的新目录，避免覆盖工作区。
