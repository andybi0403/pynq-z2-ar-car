# 通信故障时间线与复现

## 已知事实

1. 历史同组信号线：S5 ON 发 160 个 Q1 无有效回复；仅拨 OFF 后 160/160。随后一分钟窗口内 922 条有效反馈、协议错误 0；关闭时另收 1 条。证据为 work/five_round_20261026/uart-s5-off-transport.json 和 communication_*。
2. r14 在 2026-10-26 15:22:38 的 deployment.json / live-browser.json 存在正常锁车查询，后续计数达到 248/248。不能说“从来没通过”。
3. 17:37、17:40 PYNQ 下载握手失败发生于 r16 擦写之前，恢复原应用查询也无应答。因此后来的 r16 不能解释第一次失联。
4. PC 扩展板 USB / COM10 18:02 原固件 20/20；r16 写入后 18:18 为 19/20，存在一条损坏 S1 和混入 SAFE 的原始字节。
5. 对照生产 r14/r16 HWH UART 参数、prepare_console 与主机路径，未发现能解释“0 字节”的 UART 配置差异；驱动打开前后 UART 时钟门控不同是正常现象。原生内部回环通过不证明外部两板线路通过。
6. 本轮 PYNQ 完整重启后，r16 自动服务可启动，UART 仍收不到字节；没有靠重启解决。
7. r17b 修复固件选口与多 TX 驱动风险。20:08:49 进入成功下载流程，写入 9332 字节；20:09:24 完成 128 KiB 全片比较，擦除页 0..9，范围外保持原值。
8. 用户 BOOT0=0 并 RESET 后，20:14:39 PC COM10 20/20，最后 LOCK=1、PWM=0/0、drop=0、US 有效 363 mm。
9. 20:24 S5 ON：PYNQ Q1 80 次，0 字节 / 0 回复；20:27 仅切 OFF 再测：仍 0 字节 / 0 回复。新固件没有恢复 PYNQ 路径。

## 本次究竟修了什么

原代码两个 UART TX 同时为推挽输出，并有未选中口主动诊断输出、数据口固定后的切换限制。r17b 改为未选中 TX 浮空、合法 Q1 首次选择、锁车且实际零输出并满足查询静默时间后才允许另口接管；运动报文和坏 CRC 不可抢占。12 项 ARM 模型回归通过。

这解决了确定的软件隐患；**物理串口本次仍失败，不能写“根因就是选口 / 总线冲突，已修复”。** 混合字节的按位与模型只匹配部分前缀，没有完整复现；仅作为待测假说。COM10 成功只证明电脑这条通路和应用正常。

## 接手时的对照表

| 条件 | 历史成功 | 当前最后失败 |
|---|---|---|
| 生产 PMOD TX/RX | JB9→扩展板 TX、JB10←扩展板 RX | 两根线未变，沿用用户确认 |
| S5 / BOOT0 | OFF / 0 | OFF / 0 |
| STM32 应用 | 历史旧固件 | r17b |
| USB | 历史核心板 microUSB 供电 | 本次电脑接扩展板 USB，核心板仍保持供电；具体电源通路未电测 |
| PYNQ 服务 | 历史对应版本运行 | 本轮停服务、释放 UART，原生脚本只发 Q1/PSTOP |
| 结果 | 160/160、后续一分钟正常 | 0/80，0 字节 |

S5 是串口相关开关，不把它当作核心板电源开关。核心板灯亮只证明有供电迹象，不能替代 VDD、复位脚、串口电平测量。过去用户反馈电池不能点亮核心板，这条历史差异应保留，不能简单归咎于“线接错”。

## 下一位工程师的最小定位任务

保持当前接线，保存当前固件与系统版本。先确认 ttyPS1 未被其他进程持有，复用 query_recovery_board.py 只发 Q1/PSTOP，并同时观测 FPGA 外部 TX 与 MCU 实际接收路径：需要确认“Q1 出了 PYNQ”“到达了 MCU 哪个 UART”“MCU 是否选口并回发”“回复是否到达 JB10”。测量工具或只读计数插桩能把 0 字节定位到其中一段；不要继续无证据地交换两根线。

若要增添 MCU UART RX/错误/选口计数诊断，必须在已确认可用的 COM10 路径锁车测试，保留当前完整 Flash 备份和包身份，诊断口不能重新主动驱动未选中的 TX。备用 USB 方案此前用户暂不方便改，未实际接线验证，不把它写成已部署。

当前 PYNQ 服务停止、UART 已释放；不要为界面演示把历史缓存当成实时反馈。网络连接还有独立问题：重启无网络路由时发现控制台地址出现 ENETUNREACH，HTTP 已启动但控制台 URL/token 未按预期给出；需单独修复/验证离线地址发现，不能混成 STM32 串口结论。
