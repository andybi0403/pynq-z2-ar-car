## 3. 正常接线基准：不要照临时线接法运行

JA=PMODA，JB=PMODB，数字是官方实体针号。Pmod 5/11为GND，6/12为3.3V，不能把某视角从左数第几个孔当官方针号。

| 绿色板 | 正常连接 |
|---|---|
| J1.LA3/LB3/RA3/RB3 | JB1/JB2/JB3/JB4 |
| J1.GND | 可靠PYNQ GND |
| J2.OEN | JA9，低有效使能 |
| J2.3V3、J2.GND | PYNQ 3.3V、GND；本轮选JA12/JA11 |
| J5.5ENC、J5.GND | Arduino POWER 5V(J7.4)、GND |
| 左编码器负/A/B/正 | J3.GND/LA5/LB5/5ENC |
| 右编码器负/A/B/正 | J4.GND/RA5/RB5/5ENC |

编码器六芯最外两根是电机动力，接TB6612，不接绿色转换板；中间四根要按实际方向逐根追，不能凭线色定正负。

## 4. 为什么不是简单的“新软件让编码器失效”

- 当前SCALE0会让网页测速批次位置保持0，但QEI_INFO中的seen_edge、非法计数并不由SCALE门控。最新两轮手转使用的是这些独立标志，快照epoch490→491→492。
- 本机独立重算历史round1/round2共14536条：5588条左-222/右+92、8948条左+3852/右+9934，两侧末尾非法计数均255。静止180秒汇总右轮自增19270。旧网页稳定展示不等于物理输入验收通过。
- car_qei.v哈希与历史复核、r17b绑定身份一致，未发现本次新改解码算法的证据。但文件身份不替代实际加载、针位和输入对照，不能彻底排除部署/软件问题。
- r16/r17b的bit/HWH相同；本轮没有重编译FPGA、改约束、刷STM32或改SD启动配置。GPIO诊断会临时加载官方base.bit，并在finally恢复原车bit、核验ID和SCALE。
- 两次出现U-Boot提示符，执行现有boot后能启动；原因尚未定位。日志另有journal不干净/损坏后重建提示，保留证据，不将其归因编码器，也不宣布SD完整健康。
