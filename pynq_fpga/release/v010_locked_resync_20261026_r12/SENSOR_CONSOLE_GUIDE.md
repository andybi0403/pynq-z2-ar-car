# 完整传感器联调台

## 连接与现场演示

本机桌面的“PYNQ小车控制台”和“PYNQ小车接收上位机”均使用 `tools/connect_car_console.py`：自动连接已保存的小车 Wi-Fi、等待局域网地址、核对板卡 SSH 身份、启动板上服务并获取本次令牌，再打开 Edge。小车网络 `GL-SFT1200-0a0-5G` 没有互联网，上位机不依赖外网。本次已找到的 PYNQ 地址为 `192.168.8.139`，不是旧的 `.10`；入口也支持在该局域网查找已验证板卡。

电脑端双击包内 `console_launcher.html`，这个连接页可以离线显示。桌面快捷方式也可以指向它。填写 PYNQ 地址，粘贴本次启动链接或令牌后连接；实际操控台仍由 PYNQ 提供。不要把 `wireless_page.html` 当本地独立程序打开，它需要板端 API 和视频脚本。

板端解压新版包，在该目录运行下面的启动命令。第一次部署先按 README 检查依赖并编译 native 库，旧版本的 `native-build/libcar_video.so` 可以在同平台上复用，不能使用电脑上的 DLL。

该入口先加载本包 Overlay、恢复 PS UART1，再启动无线视频、PYNQ MMIO、STM32 hybrid-v3 UART 和浏览器联调页面。默认按电机动力物理断开的台架运行。用户明确电机仍接通时，使用 `SENSOR_CONSOLE_MOTOR_MODE=connected-zero-output` 据实记录物理状态；此诊断方式只发送查询和停车，不开放驾驶，也不允许应用标定。

```sh
chmod +x start_sensor_console.sh
sudo ./start_sensor_console.sh
```

默认运行 1800 秒并创建新的 `evidence/sensor_console_<UTC时间>` 目录。可用环境变量：

```sh
sudo env SENSOR_CONSOLE_DURATION=1800 \
SENSOR_CONSOLE_VIDEO_MODE=auto \
SENSOR_CONSOLE_EVIDENCE=evidence/full_sensor_run \
./start_sensor_console.sh
```

连接失败时先区分：浏览器无法打开地址，说明该地址的网页服务没有响应；页面能打开但提示令牌无效，需要本次启动的新链接；进入后提示 STM32 等待，则是板间回传状态。连接请求有超时，失败后可直接重试。

STM32 核心板灯亮只说明供电指示存在，不等于程序已运行。当前固件没有原生 USB 虚拟串口；直接将核心板 microUSB 接电脑，不能当成 USB 转 TTL 或 ST-Link 使用。2026-10-25 用户确认电池单独不能点亮核心板，需要 microUSB 供电；这项供电异常与 UART 无回包分别记录，尚不能认定根因。

2026-10-26 实板恢复接法：PYNQ **PMOD B 第9针（JB9）接扩展板蓝牙/WIFI 口的 TX，第10针（JB10）接 RX，GND 共地，VCC 不接，S5 保持 OFF**。这里的 TX/RX 是扩展板丝印视角。JA=PMOD A，JB=PMOD B；核心板两侧排针已插入扩展板，不要求在这些排针上另外插线，SWIO/SWCLK 也不能代替串口。本次对照中，S5 ON 时 160 次查询无 S1，切到 OFF 后 160/160 应答，随后一分钟 UART→PS→PL 验证通过。通信通过不替代视频、编码器标定及整车验收。

本启动脚本启用 `--diagnostic-startup`。如果采集健康检查失败，网页仍可用于定位，顶部明确显示失败原因；本次运行摘要保持失败，不会自动成为验收通过。直接运行 `wireless_runtime.py` 而不加这个参数时仍执行严格启动检查。文件身份、Overlay 契约、设备打开等致命错误仍会停止启动，并在终端报告。

零输出诊断模式遇到控制循环晚一拍时，立即清除意图并请求停车，记录 `control_schedule_overrun`、最大延迟和本轮验收失败，重新从当前时间安排采样，网页继续显示。严格模式及任何允许运动的控制策略仍会按原门禁退出，不允许用诊断恢复来掩盖驾驶时序错误。状态以完整快照一次发布，浏览器不会读到半组装的样本。

连接电机但禁止运动的诊断模式中，串口强制只发 Q1/PSTOP。当三条 CRC、当前会话及新鲜查询都匹配的锁车零输出回包显示两路采集计数同时回退，先撤销旧数据与所有旧意图，再换新随机会话重同步；不直接接纳回退报文。PL 的采样基线由唯一 MMIO 所有者在新采集代次到来时撤销并重建。普通链路仍严格拒绝回退，坏 CRC、旧会话、单通道回退和重复查询不能触发该恢复。发生过重同步的诊断轮保留失败记录，页面提示检查供电与复位原因，不能据自动恢复宣称硬件稳定。

## 最后一轮测试

先做短联调：连接成功后点击重新开始联调统计，分别遮挡并移开左右红外，改变超声波前的障碍距离，手转两个被测车轮。编码器通过条件检查位置计数的真实变化；零速采样序号增长不等于轮子转动。无效红外不计入覆盖，串口故障在本轮统计中保留。

短联调结束后导出当前联调报告，再用新的证据目录启动 1800 秒运行。演示时切换原图与处理图、冻结同帧对比，并观察接收和实际绘制帧率。断开 Wi-Fi 后页面应清除数值，恢复后重新接管；服务重启后应返回连接页并要求新令牌。需要测试断线时，单独新开一轮，不与无故障长稳记录混用。

1800 秒结束后服务会退出，最终日志在 PYNQ 的本次 `evidence` 目录，包括 `joint.jsonl`、`joint_summary.json` 和 `wireless_summary.json`。请通过文件传输保留这些文件；服务结束后网页下载链接不可用。运行中可点击导出当前联调报告，保存浏览器观察与板端状态。

页面的 10 秒联调通过只表示通道被观察到，不能代替 1800 秒长稳。最终检查实际运行时长、failures、逐分钟采集/处理/发送帧率、浏览器实际绘制帧率、串口错误和停止反馈；720p30 仍以这次实测为准。未测量的轮径、制动及 HDMI 实屏项目保留待验收。

终端会打印带本次随机令牌的浏览器地址。页面同时显示：

- 摄像头与真实 PL 处理画面；
- STM32 hybrid-v3 查询/回包计数、回包年龄、延迟和协议错误；
- 超声波距离与左右红外状态；
- QEI0/QEI1 编码器原始序号、有效性和速度寄存器；
- STM32 实际 LOCK、PWM、FAULT、drop；
- 可重置的完整联调统计。

页面启动后先进入连接界面。可以粘贴终端打印的完整启动链接，也可以填写 PYNQ 地址并只粘贴 `token`。启动链接会自动登录；桌面快捷方式打开的基础地址会停留在连接页。连接成功后浏览器写入本次 HTTP-only 会话 Cookie，随后进入操控界面。点击“断开连接”会清除该 Cookie；令牌过期或服务重启后也会退回连接页。

联调通过要求至少持续 10 秒，并观察视频、STM32 回包、超声波、左右红外、锁车反馈和两个编码器通道。页面会明确提示需要遮挡哪一侧红外或手转哪个车轮。统计只来自本次实际回传，不使用请求值、缓存值或页面模拟数据。

该通过结论只覆盖当前会话的传感器互联。轮径标定、制动时延、HDMI 实屏、电池长稳和整车 release 仍需独立验收。
