# 联合状态页面与HDMI显示

当前接口为v0.9。本说明适用于通过完整布线及包核验的同版LAB_ONLY候选；旧包不能搭配新运行软件。完整构建结果不代表实板通过，硬件状态以实际验收记录为准。

2026-10-13 新增网页运动估计显示。网页的轮速、路程、位移来自独立显示层；按展示要求，界面文案省略“估计”，内部 `estimated=true` 与模式标记保留；正常时平滑和限速变化，短时失效最多保持 1 秒，持续失效时只使用新鲜的实际锁车零输出反馈或显式导入的实测 PWM—速度模型。原始 `speed_valid`、`odometry_valid`、寄存器、控制决策和 HDMI 历史测量继续保留，估计不会变成实测标定或运动放行依据。

确实处于静止台架时可在命令中增加 `--display-stationary`，显示为“静止展示”，当前周期的估计速度和新增估计路程均为 0；移动时应关闭该选项。无线纯视频模式同样支持它，并要求 `--motor-disconnected`。这项假设不绕过联合运行的采集就绪检查；带持续坏输入的展示可使用既有 `--video-only`，仍不能获得联合验收通过。

运行时模型通过 `--display-model 文件.json` 导入。JSON 字段为 `schema=car-display-drive-model/v1`、`measured=true`、非空 `provenance` 及 `points`；points 为递增的 `[非负PWM, 实测mm/s]` 列表，首点必须为 `[0,0]`，至少还有一个实测点。模型在测得范围内线性插值，正反符号跟随实际 PWM；缺少新鲜实际反馈或超出测量范围时不外推。当前未提供真实非零 PWM—速度测量文件，软件测试的模型夹具不得用于板端标定。

在PYNQ有线连接后，从同版包目录启动。电机保持断开，HDMI显示器与USB摄像头接好：

```sh
python3 system_runtime.py --motor-disconnected --duration 1800 --video \
  --web-bind 0.0.0.0 --web-port 8080 --calibration calibration.json
```

`calibration.json`必须是已保存、轮映射正确的标定文件。没有实测标定时省略该参数，速度/里程允许保持无效，不能把名义轮径当成实测结果。运行器只打开一次Overlay，视频和页面不能另开MMIO或重新加载板上程序。

终端输出页面地址及会话令牌。将`0.0.0.0`换成PYNQ的实际有线IP，再在电脑浏览器打开完整链接（保留`#token=…`）。页面可查看障碍距离、双轮均速、路程、位移、PL停车请求、STM32实际锁存、故障和显示诊断；可预览并排队应用标定文件、保存当前配置、下载日志、停止本次运行。配置写入由现有控制线程执行。无电机模式不提供非零驾驶或释放按钮。

运行结束时先停止硬件并生成`joint_summary.json`。页面默认再保留60秒供下载；`--web-linger`可设0到300秒。完整`joint.jsonl`也保存在指定`--evidence-dir`目录。退出状态不是实板验收结论，仍需审核日志是否满足完整联合指标。

从同版包目录执行独立日志审核，包目录与标定文件必须使用本次实际部署的文件，不能从日志头复制预期身份：

```sh
python3 joint_evidence.py --directory evidence/joint \
  --package-dir . --calibration calibration.json
```

默认要求1800秒有效运行、至少25fps、逐帧时间关联可重算、控制采样间隔不超过150ms、持续新鲜的锁存零速CAR回传、传感器及里程有效。还会逐个核对包内运行源码、bit/HWH和标定来源，冻结或明显偏离100MHz的PL时间不能通过。软件夹具只能用`--software-only`审核，不能获得实板通过结论；日志审核也不证明曝光到屏幕的延迟、电气接线或机械制动性能。

HDMI状态行：V速度（mm/s），D障碍距离（mm）；新增M累计路程（mm）、D带符号位移（mm）、R风险原因位图（十六进制）、L实际LOCK（1锁存、0已解除）、F实际STM32故障位图（十六进制）、P实测方向（+前进、-后退、0静止）。无标定、异常、范围溢出或UART回传过期显示F并变为紫色。反馈年龄超过700ms后保持无效，不在时间回绕时复活。显示不改变安全判断。

速度/距离/里程/方向和R风险原因随对应解码帧传输，风险边框/STOP和L实际LOCK/F故障保持最新状态。它们在各自已接受SOF提交。帧标记错误、未来时间或超过200ms使历史数值无效；视频重复时沿用原帧身份，不能给旧帧续期。DISPLAY_FRAME_ID/STATE/TS/AGE及HEADER_ERRORS/REPEATS/TAG_COUNT可从日志的display字段查看。DISPLAY_FRAMES仍只是输出流SOF计数，不能当作摄像头原始曝光编号。接收至提交与PL流身份已经可记录/核验，曝光至屏幕扫描的延迟仍需实测。
