## 一、三个重要纠错（直接影响codex原计划）

调研发现codex原开源承接架构中有三处需要修正：

| # | codex原计划 | 调研事实 | 修正方案 |
|---|---|---|---|
| 1 | "PYNQ_Peripherals超声波接入"作为超声波链路的承接点 | 该仓库2021年重建后只剩Grove/Arduino/Pmod外设的**Python+C驱动（BSD-3）**，**无任何Verilog/FPGA IP**。IOP路线（MicroBlaze跑C固件）不构成"PL端自研"，校赛有被判"FPGA仅作数据搬运"的风险 | 超声波改为**自研AXI-Lite IP**，核心状态机从yunkai1841/HC-SR04-FPGA（CC0-1.0公共领域）移植，法律上可直接并入交付 |
| 2 | （隐含）可使用Xilinx官方Quadrature Encoder核 | **本机Vivado 2026.1环境的IP目录中未检索到可直接采用的PG139编码器核**（4403个IP条目全文检索无命中，官方文档页为空壳）；该核的历史版本变迁未获充分证据，且AMD 2026.1另有Vitis Motor Control资料可查。结论仅限本机环境： | 此项历史取舍已被09报告的AMDC结构参考路线更新；实际为同步/滤波/跃迁表解码及候选PL周期法测速，来源与贡献按文件登记 |
| 3 | PYNQ_Composable_Pipeline"学习正式PL视频架构" | 该仓库**没有OSD IP**（src下仅16个Vitis Vision HLS核）；且构建绑死Vivado 2020.2，无法在2026.1直接复用。可取的是`boards/Pynq-Z2/ip/hdmi_tx_1.0/hdl/`的**HDMI串化编码Verilog**（7系通用）和"AXI4-Stream Switch运行时重连流水线"思想 | 只抄HDMI编码器与Python驱动写法（libs.py），不整体引入其overlay；OSD改为三积木拼装自研（见第三节B） |

许可证红线备忘：AdriaanSwan/Verilog-Quadrature-Decoder-I2C-Slave为**GPL-2.0有传染性，严禁并入**；khuonglha1918（OSD+FPS）、Yourigh、bryonkucharski均**无许可证**，只读思路不抄代码；suoglu/HC-SR04为CERN-OHL-W弱互惠，不复制文件只学结构。

## 二、AMD官方选题指南中可取的部分

全国赛AMD指南与校赛方向三赛道不同，但其**方法论、指标口径与官方资源**可直接搬用，对应校赛评分项如下：

### 2.1 具身智能赛道的量化指标体系 → 「性能评估15分 + 优化改进15分」

AMD指南3.2.4对指标口径的要求远比校赛严格，直接照它的口径设计我们的测试，评委观感会明显高于本科校赛平均水准：

| AMD指标口径 | 搬用到本项目的做法 |
|---|---|
| 端到端延迟报告**P50/P95/P99和最大值，不能只给平均值** | 测"传感器采样→风险判断→HDMI画面更新/STM32停车指令"的完整链路延迟，Python打时间戳+逻辑分析仪抓Echo到GPIO，报分位数 |
| **任务闭环成功率**（须预先定义成功/失败/人工干预） | 定义"障碍物场景下正确降级/停车"为成功，做N=30次重复测试，报成功率与人工干预次数 |
| **FPGA/Zynq可量化贡献**（处理延迟、持续吞吐率、控制抖动、CPU占用，并说明**为何不能由转接板或软件替代**） | 给出三组对照数据：纯PS软件测速 vs PL测速的CPU占用；纯Python叠加 vs PL OSD叠加的延迟；用数据证明PL不可替代——这正是评分细则里"优化与改进15分"要的"验证优化措施的效果" |
| **控制周期抖动/截止期未命中率（Deadline Miss Rate）** | PL风险状态机固定100ms控制周期，PL时间戳统计周期抖动与超期次数 |
| 通信性能（RTT、丢包率、指令超时率） | PYNQ↔STM32 UART链路统计帧错误率与超时停车触发次数（STM32固件已有该机制，补记录即可） |

### 2.2 metrics/证据组织方式 → 11月1日提交材料

AMD指南3.2.5.2的指标汇总表表头（**指标名称｜类别｜数值｜单位｜测量条件｜测试次数/时长｜证据文件**）可直接套用为校赛设计报告附录；`logs/`原始CSV+`scripts/`可重跑测试脚本+`evidence/`示波器/逻辑分析仪截图的三件套组织方式照搬。校赛明确要求"设计文档"，按此组织远比贴截图堆文字有说服力。

### 2.3 推荐目录结构 → 提交前工程组织

AMD指南3.2.5.5的`docs/（architecture/interface/hardware_setup）+ fpga/（src/build/report）+ host/ + metrics/ + skill/ + report/`结构，可作为11月提交时重组工程的模板（注意：用户已决定现阶段不维护工程骨架，此结构仅在提交前一次性套用）。

### 2.4 Skill沉淀 → 创新性10分 + 全国赛入场券

AMD指南3.2.2.5和3.3.5.2都把"从失败中提炼可复用经验"列为评分/加分项，全国赛自主选题组更占15分。我们调试中已产生的高价值经验可顺手沉淀成skill/踩坑清单：
- CH340串口故障的最小固件隔离定位法（核心板单独+DAP vs 插回底板对照）
- STM32安全固件的上电锁车/超时停车/人工解锁状态机
- JDY-23 BLE 5.0不能用系统蓝牙配对、需BLE应用连接
- 5V Echo电平分压进3.3V PL的设计
这些校赛不要求，但"优秀作品推荐参加全国FPGA竞赛"，届时技能包直接复用。

### 2.5 学习资源（AMD指南3.2.7/3.3.7列出）

### B. PL硬件OSD（基础要求3：AR叠加，自研核心之一）

以下是智谱已调研的参考模块，仍需协议适配和集成验证；不得将仓库主许可证自动覆盖字体等资源：

| 资源 | 许可证 | 取什么 |
|---|---|---|
| projf/projf-explore | RTL主许可证**MIT**，但`font_unifont_8x16.mem`（GNU Unifont字模）**带独立字体许可证与版权**——若采用该字模，必须在NOTICE中单独登记其字体许可与来源，不得随仓库整体声明MIT；更简做法是改用公有领域字模或自绘16x16字模 |`lib/graphics/`的draw_char.sv、draw_rectangle.sv（fill/边框）、字模mem文件 |
| Derek-X-Wang/VGA-Text-Generator | MIT | Pixel_On_Text2的"坐标比较→字符像素替换"逻辑、Font_Rom 8x16 ASCII字模 |
| alexforencich/verilog-axis | MIT | AXIS打拍/帧同步辅助模块 |

**候选OSD IP架构**（代码行数不作为工期依据；AXIS握手、ROM延迟、帧边界提交与验证均计入工作量）：VDMA→AXI4-Stream进OSD→像素坐标计数器→三路并行判断后像素级mux：
1. 矩形框：坐标落入边框带→替换为预警色（绿/黄/红对应三级风险，颜色由AXI-Lite寄存器控制）；
2. 字符：`(x>>3,y>>4)`索引字符RAM（PS经AXI-Lite写入字符串）→`(x[2:0],y[3:0])`索引字模ROM→bit为1替换像素；
3. 图标：16x16位图ROM画风险/箭头图标。
参数（框坐标、风险等级、字符缓冲）全挂AXI-Lite，PS端Python每帧更新。

**开发期原型**：官方opencv_face_detect_hdmi.ipynb模式——`frame.array`就是VDMA显存，`cv2.putText/rectangle`直接画上去验证界面布局；验收前把putText翻译成字符RAM写入、rectangle翻译成框坐标寄存器，Python代码变成参数下发端，一行不废。

**拿分点**：同一界面做"纯Python叠加 vs PL OSD叠加"的延迟/CPU占用对比 → 优化改进15分的直接证据。

## 四、修正后的开源承接架构（V2）

```
官方PYNQ-Z2 Base Overlay（video notebooks，BSD）
  → 视频链路：USB/OpenCV取流→DDR→VDMA（照codex原方案，不变）
  → HDMI编码Verilog：取自PYNQ_Composable_Pipeline（BSD，7系通用）
  → OSD自研IP：projf-explore(draw_char/rectangle) + Derek-X-Wang(坐标比较/字模)
      + alexforencich/verilog-axis(AXIS plumbing)，按模块核实许可，工期包含协议适配与独立逐像素验证
  → 编码器测速自研IP：fpga4fun x4解码思路重写 + M/T法 + AXI-Lite模板
  → 超声波测距自研IP：yunkai1841(CC0)核心移植 + 2FF同步器 + AXI-Lite模板
  → 风险状态机：团队独立实现（动态安全距离公式为常规ADAS制动模型的应用；未做完整的先例检索，不排除已有类似实现，不得在报告中断言"无先例"）
  → 检测闭环（拓展）：2cc2ic(MIT)画框思路 + 官方face-detect混合架构
  → 面板/远程/孪生：ipywidgets + Flask MJPEG/UDP JSON + matplotlib（PS端，全部PS生态）
```

自研比例与合规声明：OSD/编码器/超声波分别借鉴开源积木与状态机思路，**每个并入或改写的外部文件须登记来源仓库URL、提交号、文件路径、许可证、采用方式与修改范围**（MIT/CC0/BSD允许复用但条件不同）；寄存器映射、风险状态机、动态安全距离模型、统一时间戳关联机制为团队独立实现。引用登记是诚实申报的必要条件，但不自动等于竞赛对"原创"的认定。
