## 现在先准备什么

保留当前ZIP与构建结果，整理实际接线照片、板卡修订版、电源及电平转换资料。核对万用表、网线、TF卡、读卡器、USB摄像头和HDMI显示器是否具备；没有确认的物品不记为已准备。

制作一份空白实测记录，留出左右编码器计数、加载滚动距离、方向、UART停车时延、屏幕色序和故障场景字段。现在不填测量结果、不把名义轮径标成实测。接线检查依据[无电机验收规程](../../pynq_fpga/fpga/board/no_motor_acceptance.md)及[编码器电气与参数核定](10_霍尔编码器TT马达电气与QEI参数核定_20260919.md)。

具备上板条件后，先确认能登录PYNQ、提供实际IP和用户名，并确认电机动力线已物理断开，再进入下面流程。当前LAB_ONLY不提供非零驾驶或释放；整轮验收保持电机断开。

## 到板后的执行顺序

| 阶段 | 做什么 | 进入下一步的依据 |
|---|---|---|
| 1：启动与部署 | 核对电源/板卡/电平，启动系统，建立网络登录，复制并解压完整候选包 | 可登录；板端依赖与包契约检查通过 |
| 2：基本硬件 | 加载Overlay，读取MMIO快照，检查版本与epoch推进 | ID正确、快照持续推进、无读写异常 |
| 3：传感器与UART | 检查US/IR正常与故障条件，验证UART STOP及新锁存零速回传 | 每个场景有独立原始记录；停车响应不超过300ms |
| 4：双轮标定 | 电平验收后手动转轮/滚动，核对左右映射和方向，计算并保存双轮配置 | 有实测依据的calibration.json，配置/读回及里程方向验证通过 |
| 5：摄像头与显示 | 先色条，再USB摄像头，检查色序、OSD与帧率 | 屏幕照片、帧率记录和显示身份记录齐全 |
| 6：短时联合与异常 | 同一会话运行30秒，检查页面、日志和各链路；另开独立场景测试拔出相机/串口等异常 | 短跑正常；异常按预期停止/记录，退出后资源已确认回收 |
| 7：正式联合验收 | 恢复正常接线与健康采集，固定实测标定，独立新会话运行1800秒，再审核日志 | 完整联合审核通过，人工电气/机械/显示记录也齐全 |

每一阶段结束后再运行下一阶段，不同时启动独立视频、安全循环或第二个Overlay会话。故障注入和正常30分钟稳定性测试分别保存；不能把故障段删掉后把同一日志改成正常PASS。

## 可直接使用的板端命令

以下在PYNQ终端、完整部署目录内执行。设备路径使用实际检查结果，默认相机`/dev/video0`、串口`/dev/ttyPS1`。

### 1. 部署与文件核验

```sh
cd ~/task7_8_lab_only_v09_complete_20260930_r2
python3 --version
python3 deployment_check.py --board --output evidence/deployment.json
python3 lab_acceptance.py contract
```

当前运行程序要求Python 3.10及以上。依赖或设备检查失败时，先解决失败项；此处只读检查不加载FPGA、不打开串口。摄像头和串口尚未接入时，设备缺失是明确待处理项。

### 2. Overlay与快照

```sh
python3 lab_acceptance.py mmio --evidence-dir evidence/mmio_initial
```

保存`mmio.json`，确认ID、epoch和原始状态。首次未接传感器/未标定时的无效状态用于定位原因，不算完整传感器验收通过。

### 3. 传感器和UART STOP

```sh
python3 lab_acceptance.py sensor-check --label normal --count 10 \
  --expect-us-valid 1 --expect-us-fault 0 --distance-min 250 --distance-max 2000 \
  --expect-ir-valid 1 --expect-ir-stable 1 --expect-ir-mask 0 \
  --evidence-dir evidence/sensors_normal
python3 lab_acceptance.py uart-stop --port /dev/ttyPS1 --duration 3 \
  --stop-deadline-ms 300 --motor-disconnected --evidence-dir evidence/uart_stop
```

正常场景要求目标位于250—2000mm且红外无遮挡。无回波、Echo卡高、左右遮挡等条件按包内README与无电机规程逐个测试，每次使用独立标签/目录。记录实际条件，不能直接修改日志模拟故障。

### 4. 标定文件

先记录左右轮实际编码器计数、加载滚动距离、正反方向和非法边沿情况，再计算各自SCALE，使用配置保存接口或状态页面保存完整`calibration.json`。文件应含左右scale/direction/filter_ticks/zero_ticks、固定左右通道映射、当前契约版本、测量来源与measured状态；格式由包内`calibration_config.py`校验。

名义轮径/预设SCALE只用于初步排查，不能直接作为最终measured标定。缺少实测配置时留在分项检查，不进入正式联合验收。联合入口会在自己的共享会话中应用配置并读回，不依赖之前某个独立命令碰巧保留的寄存器。

### 5. 视频单项

```sh
python3 lab_acceptance.py color-bars --hold-seconds 30 --evidence-dir evidence/color_bars
python3 lab_acceptance.py camera --camera-device /dev/video0 --frames 900 \
  --min-fps 25 --max-p95-ms 50 --max-drop-rate 0.05 \
  --evidence-dir evidence/camera
```

人眼核对RGB色序和显示，保留照片。脚本报告帧提交不等于屏幕色序通过；输出帧率也不等于已测摄像头曝光至屏幕延迟。

### 6. 30秒联合试跑

```sh
python3 system_runtime.py --motor-disconnected --duration 30 --video \
  --port /dev/ttyPS1 --camera-device /dev/video0 --calibration calibration.json \
  --web-bind 0.0.0.0 --web-port 8080 --evidence-dir evidence/joint_30s
```

浏览器将打印地址中的`0.0.0.0`替换为板端实际IP，保留会话令牌。观察距离/速度/里程、PL风险、STM32真实LOCK/FAULT和画面身份，尝试日志下载。正式计时前最多等待5秒，要求静止健康状态持续300ms；就绪失败先修正具体原因，不跳过检查。

异常测试另用新目录保存。确认UART关闭、摄像头子进程与视频线程退出、DMA/HDMI可停止。若报告“resource termination unconfirmed”，先确认驱动与进程已终止，不能当作回收通过或直接启动下一会话。

### 7. 30分钟联合与独立审核

```sh
python3 system_runtime.py --motor-disconnected --duration 1800 --video \
  --port /dev/ttyPS1 --camera-device /dev/video0 --calibration calibration.json \
  --web-bind 0.0.0.0 --web-port 8080 --evidence-dir evidence/joint_1800s
python3 joint_evidence.py --directory evidence/joint_1800s \
  --package-dir . --calibration calibration.json
```

30秒记录不会满足1800秒门禁。正式会话保持标定固定、原始采集健康；不要在测试中途改配置。审核要求包/标定来源一致、持续新鲜CAR与锁存零输出、采样间隔不超过150ms、视频至少25fps以及逐帧关联/显示诊断可重算。命令退出成功、页面显示正常和独立联合审核通过分别记录，不能混为一个结论。

最后带回`startup_readiness.json`、`joint.jsonl`、`joint_summary.json`、审核输出、实际标定文件和人工测量/照片。审核输出请另存文件；原始日志不要手工修改。只有所有必需实物证据核对齐全，才能审议1—8完成和后续发布；接电机、机械制动与运动测试另定流程，不在当前LAB_ONLY命令范围内。

## 失败时怎么接着做

停在最先失败的阶段，保留原始日志和实际接线状态，定位原因后以新目录重试。源码或硬件工程需要修改时，通过[完整重建入口](../../pynq_fpga/preintegration/COMPLETE_BUILD.md)生成新的同版包；不要往已验收候选里混入单独更新的运行脚本。仅更新这份工作流程不改变已有部署ZIP与构建哈希。
