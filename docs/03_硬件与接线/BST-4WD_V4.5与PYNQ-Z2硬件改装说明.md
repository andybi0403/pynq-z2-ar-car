# BST-4WD V4.5 小车与 PYNQ-Z2 硬件改装说明

## 1. 文档目的与版本基线

本文用于回答以下问题：

1. 已组装的亚博 BST-4WD 小车需要修改哪些部件，才能与 PYNQ-Z2 协作。
2. PYNQ-Z2、STM32、传感器和显示设备应当怎样连接。
3. 原车哪些部件继续保留，哪些部件在本项目中用不上。
4. 2022 年购买、使用蓝牙 4.0 的小车应当怎样处理。
5. 各部件对应的本地硬件资料和程序依据是什么。

已经确认的实物版本为 **BST-4WD V4.5，三节锂电池版，蓝牙 4.0**。

资料包中的 `YB-EVF01 VER4.5.pdf` 文件名标注 V4.5，但图纸标题栏仍写 `BST-4WD V4.4`。本文将其作为 V4.5 资料包所附电路参考，同时用接口速查表和 STM32 源码交叉核对关键引脚。最终接线时仍应对照实物丝印，不能仅根据连接器外观判断方向。

## 2. 最终结论

不需要把四个电机或 TB6612 电机驱动改接到 PYNQ-Z2。

最终只需要完成四类改装：

1. 在小车上安装 PYNQ-Z2、USB 摄像头及独立电源。
2. 将超声波的 Trig/Echo 信号从 STM32 迁移到 PYNQ PL。
3. 左右两侧各增加一个 A/B 编码器，并将四路编码信号接入 PYNQ PL。
4. PYNQ 通过 UART 向原车 STM32 发送驾驶指令；STM32 继续控制 TB6612 和四个电机。

```text
电脑 ──网线──→ PYNQ PS
                   │
USB摄像头 ────────→│ 图像采集、配置、日志
                   │
左右编码器 ───────→ PYNQ PL：测速、里程、风险判断、硬件叠加
前向超声波 ───────→│
                   │
                   ├──HDMI OUT──→ 显示器
                   │
                   └──UART──→ STM32 ──→ TB6612 ──→ 四个电机
```

PYNQ 负责感知、计算和最终驾驶限制；STM32 负责可靠执行以及通信失联时的本地停车。

## 3. 原车部件处理结论

### 3.1 必须保留

| 部件 | 处理方式 | 说明 |
|---|---|---|
| STM32F103C8T6 核心板 | 保留 | 解析 PYNQ 指令、产生方向和 PWM、执行超时停车 |
| TB6612FNG | 保留 | 原车四电机功率驱动，不由 FPGA GPIO 直接替代 |
| 四个直流减速电机 | 保持原接线 | 同侧两个电机共用一路驱动和 PWM |
| BST-4WD V4.5 扩展板 | 保留 | 继续承担电源、驱动、下载和底盘接口功能 |
| CH340 下载电路 | 保留 | 继续烧录和调试 STM32 |
| 三节锂电池、开关和动力线束 | 保留 | 仅供原车动力系统使用 |
| 电池电压检测 | 建议保留 | 由 STM32 采集后通过 UART 上报 |
| 蜂鸣器和启动按键 | 建议保留 | 用于故障、使能和停车提示 |

原车电机引脚：

| 功能 | STM32 引脚 |
|---|---|
| 左侧方向 AIN2/AIN1 | PB9 / PB8 |
| 左侧 PWM PWMA | PB7 |
| 右侧方向 BIN2/BIN1 | PB4 / PB5 |
| 右侧 PWM PWMB | PB6 |

### 3.2 迁移到 PYNQ

| 部件或信号 | 原连接 | 最终连接 |
|---|---|---|
| 超声波 Trig/Echo | STM32 PA15/PA12 | PYNQ Pmod B，经必要的电平转换 |
| 左编码器 A/B | 原车没有 | PYNQ Pmod B |
| 右编码器 A/B | 原车没有 | PYNQ Pmod B |
| USB 摄像头 | 原车没有 | PYNQ USB Host |
| AR 视频输出 | 原车没有 | PYNQ HDMI OUT |
| 底盘控制链路 | 蓝牙 4.0→STM32 | PYNQ UART→STM32 |

### 3.3 可选保留，但不进入第一版主线

| 部件 | 建议 |
|---|---|
| MPU6050 | 后续姿态/转向估计扩展；基础版暂不接 PYNQ |
| RGB 探照灯 | 可改作绿、黄、红风险提示，也可以停用 |
| 云台舵机 | 第一版将超声波固定正前方，舵机保持中位或拆下 |

### 3.4 基础项目用不上

- 四路巡线模块。
- 左右红外避障模块。
- 左右寻光模块。
- 灰度传感器。
- 红外遥控器和接收头。
- PS2 手柄接收器。
- NRF24L01 无线模块。
- 线性 CCD。
- 手势识别臂环。
- 灭火风扇。
- 机械臂及多舵机扩展。
- 蓝牙 5.0/JDY-23 资料和程序。
- PYNQ 接管通信之后的蓝牙 4.0 模块。

不用的模块如果是插接式，可以拆下以减少耗电、线束混乱和误触发；扩展板上的空插座不需要拆除。

## 4. PYNQ-Z2 Pmod B 接线分配

Pmod B 的八根信号线正好覆盖四路编码器、两路超声波和两路 UART。

| Pmod B 实体脚号 | FPGA 封装脚 | 项目用途 | 相对 PYNQ 方向 |
|---:|---|---|---|
| 1 | W14 | 左编码器 A | 输入 |
| 2 | Y14 | 左编码器 B | 输入 |
| 3 | T11 | 右编码器 A | 输入 |
| 4 | T10 | 右编码器 B | 输入 |
| 5 | — | 公共信号地 | — |
| 6 | — | 3.3V，仅供小功耗电平转换逻辑 | 电源 |
| 7 | V16 | 超声波 Trig | 输出 |
| 8 | W16 | 超声波 Echo，必须是安全的 3.3V 电平 | 输入 |
| 9 | V12 | UART TX，发往 STM32 | 输出 |
| 10 | W13 | UART RX，接收 STM32 数据 | 输入 |
| 11 | — | 公共信号地 | — |
| 12 | — | 3.3V，仅供小功耗电平转换逻辑 | 电源 |

Pmod 管脚使用 `LVCMOS33`。不得把 5V 信号直接接入 PYNQ。

官方依据：

- [PYNQ-Z2 Reference Manual v1.1](https://dpoauwgwqsy2x.cloudfront.net/Download/PYNQ_Z2_User_Manual_v1.1.pdf)
- [PYNQ-Z2 官方 base.xdc](https://github.com/Xilinx/PYNQ/blob/master/boards/Pynq-Z2/base/vivado/constraints/base.xdc)

## 5. PYNQ 与 STM32 的 UART 接法

原蓝牙控制工程实际使用 STM32 USART2：

- PA2：STM32 TX。
- PA3：STM32 RX。
- 当前程序配置：9600、8 数据位、1 停止位、无校验。
- 原协议使用 `$` 开始、`#` 结束的文本帧。

V4.5 蓝牙/WiFi 插座 K1 按资料中的电气脚序连接：

| K1 脚号 | 板上信号 | PYNQ 连接 |
|---:|---|---|
| 1 | VCC | **不连接** |
| 2 | GND | 接 Pmod B 5 或 11 脚 |
| 3 | TXD，来自 STM32 PA2 | 接 Pmod B 10 脚，PYNQ RX |
| 4 | RXD，进入 STM32 PA3 | 接 Pmod B 9 脚，PYNQ TX |

接线原则：

- TX 和 RX 必须交叉。
- 两块板只连接 TX、RX、GND，不连接正电源。
- 蓝牙模块与 PYNQ 不能同时驱动同一路 UART。
- 初次联调先保持 9600、8N1，验证无误后再同时把双方升级到 115200。
- USART1 的 PA9/PA10 与 CH340 下载电路相关，不作为首选常驻通信接口。

## 6. 蓝牙 4.0 的处理方式

蓝牙 4.0 不需要立即拆除：

1. PYNQ 未到货和 STM32 单独测试阶段，继续使用蓝牙 4.0 验证前进、后退、转向和停止。
2. PYNQ 到货并开始板间联调时，断电后拔下蓝牙 4.0 模块。
3. 将 PYNQ UART 接到原 K1 插座对应的 RXD、TXD、GND。
4. 蓝牙模块保存作为原车恢复和故障排查工具，不进入最终比赛控制链路。

资料包中 `蓝牙5.0模块` 文件夹内的 JDY-23 资料不适用于这辆车。蓝牙版本变化不影响底盘电机程序，因为蓝牙本质上只是 USART2 的无线透传通道。

亚博蓝牙 4.0 参考：[Bluetooth 4.0 module](https://www.yahboom.net/study/BT4)

## 7. 超声波迁移方案

资料中的 J17 超声波接口为四线接口：

| J17 脚号 | 信号 | 原 STM32 连接 |
|---:|---|---|
| 1 | VCC | 板上电源，实物需测量确认 |
| 2 | SCL_C，即 Trig | PA15 |
| 3 | SDA_C，即 Echo | PA12 |
| 4 | GND | 公共地 |

最终连接：

```text
小车板经过测量确认的传感器电源 ──→ 超声波 VCC
小车板 GND ─────────────────────→ 超声波 GND ──→ PYNQ GND
Pmod B 7/Trig ──必要时3.3V转5V──→ 超声波 Trig
超声波 Echo ──5V转3.3V──────────→ Pmod B 8/Echo
```

注意事项：

- 先用万用表确认 J17 VCC 和 Echo 的实际电压。
- Echo 若为 5V，必须降至 3.3V后再进入 PYNQ。
- 输入侧可以使用 3.3V 供电的 SN74LVC245A；其输入能够接收 5V信号。
- Trig 若不能被 3.3V 稳定触发，可使用 74AHCT125 或合适的单向转换器升至5V。
- 不建议使用廉价 BSS138 双向 I²C 转换板处理这些推挽脉冲。
- PYNQ 接管后，STM32 的 PA15/PA12 不再控制超声波。

旧程序不能在不修改固件的情况下直接拔掉超声波。原函数在等待 Echo 上升沿时可能长时间阻塞，而且蓝牙空闲状态仍会周期读取超声波。迁移传感器之前，必须先删除这部分旧读取逻辑。

## 8. 编码器加装方案

现有 BST-4WD 资料、接口表和蓝牙源码中都没有轮速编码器。因此真实测速和里程功能必须新增硬件。

第一版只需要两套 A/B 编码器：

- 左侧选择一个车轮安装一套。
- 右侧选择一个车轮安装一套。
- 四根 A/B 输出经必要电平转换后接 Pmod B 1～4脚。

优先级：

1. 优先加装独立磁编码器或光电码盘，不改变现有四个电机的功率接线。
2. 如果现有轮轴没有安装空间，再更换左右各一个同尺寸编码电机。
3. 不必一开始就更换四个电机，因为同侧两个电机本来共用一路驱动。

购买编码器前必须确认：

- 电机外形、安装孔和轴尺寸。
- 车轮与码盘的安装空间。
- 输出是 A/B 正交还是单通道。
- 输出电压以及开漏/推挽类型。
- 若更换电机，其工作电压、减速比和堵转电流是否匹配原车。

如果编码器输出5V推挽信号，使用 SN74LVC245A 等器件转换至3.3V；如果是开漏输出，则将上拉电阻接到3.3V，不要上拉到5V。

## 9. 摄像头、显示和供电

视频链路：

```text
USB UVC摄像头 → PYNQ USB Host → PS帧缓存 → PL硬件OSD → HDMI OUT → 显示器
```

- 摄像头连接 PYNQ 的 USB Host，不连接 Micro-USB 下载/供电口。
- 主显示器连接 HDMI OUT，不能接错到 HDMI IN。
- 电脑通过网线向 PYNQ 发送驾驶请求和读取状态。
- 第一版为有线低速演示，必须固定 HDMI、网线和电源线，避免插座承受拉力。

供电原则：

```text
原车三节电池 → BST-4WD扩展板 → STM32、TB6612、四个电机
独立稳压电源 → PYNQ-Z2 → USB摄像头
```

- 不将两路电源的正极直接并联。
- UART、编码器和超声波使用非隔离连接时必须共信号地。
- 初期不从小车传感器插座给 PYNQ 供电。
- PYNQ 官方支持 Micro-USB 供电或 7～15V 外接电源，外接时推荐 12V并核对跳线和插头极性。

## 10. STM32 固件需要修改的内容

不需要重写已验证的电机底层，主要进行以下修改：

1. 保留电机GPIO、TIM4 PWM和 `Car_Run`、`Car_Back`、`Car_Left`、`Car_Right`、`Car_Stop`。
2. 保留 USART2，初次联调沿用 9600、8N1。
3. 上电和复位完成后立即进入停车状态。
4. 删除或禁止巡线、红外避障、寻光、灰度、RGB、风扇和舵机等无关初始化。
5. 删除 STM32 超声波测量以及旧的全传感器周期回传。
6. 接收 PYNQ 的左右驱动输出、运行许可和风险状态。
7. 超过约 100ms没有收到新的有效控制帧时，STM32独立停车。
8. 帧错误、任一板复位或传感器故障时停车。
9. 故障解除后不自动恢复此前的运动命令，必须重新使能。
10. 后期将旧文本帧升级为包含版本、类型、序号、长度和 CRC 的协议。

## 11. 需要准备的新增硬件

| 优先级 | 物品 | 用途 |
|---|---|---|
| 必需 | 两套 A/B 编码器及机械安装件 | 左右轮真实测速和里程 |
| 必需 | SN74LVC245A 或等效输入转换电路 | 编码器及 Echo 的 5V→3.3V |
| 视实测需要 | 74AHCT125 或单向升电平电路 | Trig 的 3.3V→5V |
| 必需 | Pmod 2×6、2.54mm转接板或排线 | PYNQ外部信号连接 |
| 必需 | PH2.0端子、散线及压线工具 | 超声波转接线制作 |
| 必需 | USB UVC摄像头及固定架 | 视频输入 |
| 必需 | PYNQ独立电源 | 避免电机噪声干扰或损坏板卡 |
| 必需 | 网线、HDMI线 | 控制和显示 |
| 调试 | 万用表、USB串口工具、逻辑分析仪 | 电压、UART和脉冲检查 |

K1蓝牙插头和编码器的最终机械型号应根据实物尺寸购买，不能只按照接口名称下单。

## 12. 推荐实施顺序

1. 保持当前蓝牙4.0和原厂程序，验证小车前后左右及停止功能。
2. 备份可运行的 STM32 工程和固件。
3. 修改 STM32 程序，只保留电机、UART、电压检测和安全停车。
4. 暂不接 PYNQ，先用电脑USB转串口模拟 PYNQ，验证拔线超时停车。
5. 安装左右编码器，先独立观察A/B波形和电平。
6. PYNQ到货后完成镜像、USB摄像头和HDMI基础测试。
7. 断电拔下蓝牙4.0，将 PYNQ UART接入K1。
8. 迁移超声波并验证正常、无回波、持续高电平和超量程状态。
9. 轮子悬空完成编码器、超声波、UART和电机端到端联调。
10. 最后才进行地面低速停车实验。

## 13. 上电前检查清单

- [ ] 确认扩展板为 BST-4WD V4.5。
- [ ] PYNQ与STM32没有连接正电源，只连接TX、RX和GND。
- [ ] UART TX/RX已经交叉。
- [ ] 蓝牙4.0已经拔下，没有与PYNQ同时驱动USART2。
- [ ] 超声波Echo进入PYNQ前不超过3.3V。
- [ ] 编码器A/B进入PYNQ前不超过3.3V。
- [ ] Pmod B连接器方向已经按板上丝印核对。
- [ ] 小车电机离地或车辆被可靠架起。
- [ ] STM32上电默认停车，通信超时能够停车。
- [ ] 重新下载PYNQ Overlay时小车保持禁止运行。

## 15. 最终边界

本方案覆盖基础项目所需的硬件协作：摄像头视频、左右轮速、前向距离、FPGA实时处理和AR叠加、PYNQ与STM32协作以及安全停车。

它不把原车改造成全方向自动驾驶车辆，也不依赖巡线、寻光、红外避障或蓝牙遥控作为最终比赛功能。第一版限定为室内、低速、正向辅助停车和有线演示。
