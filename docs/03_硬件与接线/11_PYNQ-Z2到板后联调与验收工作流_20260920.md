## 1. 板卡本体验收与系统启动

**预计用时：30—60分钟**

- [ ] 断开TB6612电机输出或拔除四个电机动力线。
- [ ] 核对实物为PYNQ-Z2。
- [ ] 拍照记录PCB修订版、丝印、电源选择跳线。
- [ ] 将实物与本地R12原理图、PA_v3资料对照。
- [ ] 安装PYNQ系统镜像。
- [ ] 验证启动、网络与SSH登录。
- [ ] 将LAB_ONLY目录复制到PYNQ。
- [ ] 执行文件与HWH契约检查：

```bash
cd ~/task7_8_lab_only_20260919
python3 lab_acceptance.py contract
```

通过条件：

- bit与hwh匹配；
- 统一ID为`0xC4251006`；
- HWH包含生产`car_system`；
- 不存在控制或OSD占位核。

失败条件：板卡型号/修订版无法确认、契约错误、bit/hwh不匹配。失败后不得加载并连接外设。

## 2. 电源、共地与电平转换验收

**预计用时：1—2小时**

先不连接PL信号，逐项测量：

- [ ] Pmod A/B电源脚约为3.3V。
- [ ] Arduino POWER头J7 pin 4为VCC5V0。
- [ ] PYNQ地与小车地之间无危险电位差。
- [ ] SN74LVC245A供电为3.3V。
- [ ] SN74LVC245A DIR固定为A→B。
- [ ] 每片SN74LVC245A具有近端100nF去耦。
- [ ] 两块霍尔编码器板5V入口具有近端10uF+100nF去耦。
- [ ] 超声波Echo转换后不超过3.3V。
- [ ] 编码器A/B转换后不超过3.3V。

编码器供电与转换固定方案：

- 编码器4.5—5V：Arduino POWER头J7 pin 4/VCC5V0；
- 编码器A/B：经过SN74LVC245A进入JB1—JB4；
- 电机动力：仍由TB6612提供；
- 禁止从Pmod给编码器提供5V；
- 禁止5V A/B直接进入PL。

QEI `/OE`检查：

| 状态 | 预期 |
|---|---|
| PL未配置 | 外部10k上拉使`/OE`保持高，转换器禁用 |
| PL同步复位 | JA9/W18输出高，转换器禁用 |
| 复位释放 | JA9/W18输出低，转换器使能 |

证据建议：`evidence/E/03_power.csv`、`04_level_shift.csv`、`07f_qei_oe.csv`。

失败条件：任一PL输入可能见5V、异常发热、地电位异常、`/OE`上电即低或悬空。

## 3. Overlay与MMIO基础验证

**预计用时：30—60分钟**

- [ ] 加载LAB_ONLY Overlay。
- [ ] 执行：

```bash
python3 lab_acceptance.py mmio --evidence-dir evidence
```

检查：

- [ ] `INTEGRATED_ID=0xC4251006`。
- [ ] 全局快照epoch持续推进。
- [ ] US、IR、QEI和风险输出属于同一次全局快照。
- [ ] 各组保留独立`sample_ts/seq/valid`。
- [ ] QEI SCALE复位值为0，表示未标定无效。
- [ ] 未写有效`RISK_CMD`时，风险核保持`stop=1`和command-invalid原因位。

失败条件：ID错误、epoch冻结、快照撕裂、寄存器地址不符。

## 4. 超声波与红外逐项验收

**预计用时：1—2小时**

### 4.1 超声波

- [ ] 正常目标距离。
- [ ] Echo断开，预期无回波故障码1。
- [ ] Echo保持高，预期卡高故障码2。
- [ ] 检查200mm屏蔽前进与250mm恢复回差。

示例：

```bash
python3 lab_acceptance.py sensor-check --label normal --count 10 \
  --expect-us-valid 1 --expect-us-fault 0 \
  --distance-min 250 --distance-max 2000 \
  --evidence-dir evidence

python3 lab_acceptance.py sensor-check --label us_no_echo --count 5 \
  --expect-us-valid 0 --expect-us-fault 1 --evidence-dir evidence

python3 lab_acceptance.py sensor-check --label us_stuck_high --count 5 \
  --expect-us-valid 0 --expect-us-fault 2 --evidence-dir evidence
```

### 4.2 红外

- [ ] 无遮挡：mask 0。
- [ ] 左侧遮挡：mask 1。
- [ ] 右侧遮挡：mask 2。
- [ ] 两侧遮挡：mask 3。
- [ ] stable和消抖行为正确。
- [ ] 3.3V供电时检测距离满足需求。

失败条件：高电平超限、故障分类错误、mask或stable不符合物理状态。

## 5. 双前轮QEI验收与标定

**预计用时：2—3小时**

- [ ] 先完成J7 5V、LVC245两侧电平和JA9 `/OE`检查。
- [ ] 左前编码器接JB1/JB2，对应QEI0。
- [ ] 右前编码器接JB3/JB4，对应QEI1。
- [ ] 接反时只允许换线，不改软件契约。
- [ ] 分别慢速手转，检查AB相序与正反方向。
- [ ] 检查静止时无漂移、非法跳变计数正常。
- [ ] 左右各手转整10圈。

1:48、13线、x4计数的预期：

```text
13 × 48 × 4 × 10 = 24960 counts
```

若接近46800，可能拿到1:90版本，应保持SCALE=0并停止。

### 带载滚动标定

- [ ] 保持原装轮胎和正常整车载荷。
- [ ] 左右轮分别测量多圈滚动距离。
- [ ] 分别计算左、右SCALE。
- [ ] 先以5362检查速度量级，但不得将其当作最终标定值。
- [ ] 显式写入实测SCALE：

```bash
python3 lab_acceptance.py qei-config \
  --left-scale 实测左值 --right-scale 实测右值 \
  --motor-disconnected --evidence-dir evidence
```

- [ ] 检查两路读回一致。
- [ ] 检查正反转符号。
- [ ] 检查mm/s速度量级和累计距离。
- [ ] 检查QEI无效或过期会触发风险停止。

## 6. UART与真实STM32安全闭环

**预计用时：1—2小时**

- [ ] 拔掉蓝牙，避免双串口源竞争。
- [ ] 连接PYNQ UART TX/RX/GND与STM32。
- [ ] 保持电机动力线断开。
- [ ] 安装`pyserial`。
- [ ] 先只发送STOP和零速帧：

```bash
python3 -m pip install pyserial
python3 lab_acceptance.py uart-stop \
  --port /dev/ttyPS1 --duration 3 \
  --stop-deadline-ms 300 \
  --motor-disconnected --evidence-dir evidence
```

- [ ] 再运行30秒联合闭环：

```bash
python3 lab_acceptance.py safety-loop \
  --port /dev/ttyPS1 --duration 30 \
  --interval 0.05 --stop-deadline-ms 300 \
  --motor-disconnected --evidence-dir evidence
```

必须验证：

- [ ] US超龄触发停止。
- [ ] IR置位触发停止。
- [ ] QEI无效/超龄触发停止。
- [ ] UART失联触发停止。
- [ ] 250ms租约过期触发停止。
- [ ] STOP到STM32新锁存零输出不超过300ms。
- [ ] 故障恢复不会自动解锁。
- [ ] 不会重放故障前运动指令。
- [ ] 生产循环以明显小于250ms的周期续写`RISK_CMD`，建议100ms。

## 7. HDMI与C270视频链路

**预计用时：1—2小时**

### 7.1 RGB色条

```bash
python3 lab_acceptance.py color-bars \
  --hold-seconds 30 --evidence-dir evidence
```

人工检查：

- [ ] HDMI能够显示。
- [ ] RGB色序正确。
- [ ] 分辨率和画面完整。
- [ ] 风险边框和状态块正确。
- [ ] 数字、负号和无效状态正确。
- [ ] HDMI插拔后可以恢复。

### 7.2 Logitech C270

```bash
python3 lab_acceptance.py camera \
  --camera-device /dev/video0 --frames 900 \
  --min-fps 25 --max-p95-ms 50 \
  --max-drop-rate 0.05 --evidence-dir evidence
```

目标：

- [ ] 实测帧率不低于25fps。
- [ ] P95帧间隔不超过50ms。
- [ ] 估算掉帧率不超过5%。
- [ ] OSD与风险状态同步。
- [ ] 无持续黑屏、花屏或VDMA冻结。

必须保存屏幕照片和JSON证据；脚本通过不能替代人工颜色确认。

## 8. 30分钟联合稳定性测试

**预计用时：30—45分钟**

保持电机断开，同时运行视频和安全闭环：

```bash
python3 lab_acceptance.py safety-loop \
  --port /dev/ttyPS1 --duration 1800 \
  --interval 0.05 --stop-deadline-ms 300 \
  --motor-disconnected --evidence-dir evidence
```

检查：

- [ ] epoch持续推进。
- [ ] 无MMIO或VDMA锁死。
- [ ] UART无持续丢帧。
- [ ] 无异常温升。
- [ ] STOP时延持续符合要求。
- [ ] 所有故障均保持锁存和零输出。
- [ ] 没有自动恢复运动。

阶段1—8全部通过后，才允许连接电机动力并进入悬空测试。

## 9. 四轮悬空的低占空比电机测试

- [ ] 将整车可靠架空。
- [ ] 从最低PWM开始。
- [ ] 分别测试左侧、右侧。
- [ ] 检查同侧前后轮方向一致。
- [ ] 比较前编码器电机与原后电机的悬空转速。
- [ ] 观察同侧电流和机械顶牛。
- [ ] 测试前进、后退、左转、右转和制动。
- [ ] 注入IR、距离过近、QEI失效、UART断开。
- [ ] 确认故障期间电机输出始终为安全状态。
- [ ] 确认解锁需连续安全状态至少300ms、显式释放和新的驾驶意图。

失败处理：

- 同侧方向相反：换电机线；
- 编码器方向相反：换A/B或按既定硬件方案纠正；
- 同侧前后轮转速差过大：更换匹配电机或调整驱动硬件；
- 禁止用错误SCALE或PID掩盖机械不匹配。

## 10. 地面低速测试与发布门禁

- [ ] 选择空旷场地，以最低速度开始。
- [ ] 测固定距离直行。
- [ ] 比较实际距离、QEI0里程、QEI1里程和左右偏差。
- [ ] 检查同侧前后轮有无机械顶牛。
- [ ] 验证距离≤200mm只屏蔽正向。
- [ ] 验证倒车脱困仍可用。
- [ ] 验证距离≥250mm后的恢复条件。
- [ ] 实测IR、US、QEI、UART和租约故障的停止距离。
- [ ] 完成C270、HDMI、OSD和30分钟整车稳定性记录。
- [ ] 人工复核全部证据。
- [ ] 更新`board_manifest.json`中的电气与板卡状态。
- [ ] 仅在证据完整后将`electrical_ready/release_ready`改为true。
