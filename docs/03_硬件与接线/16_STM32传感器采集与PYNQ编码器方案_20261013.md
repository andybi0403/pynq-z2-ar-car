# STM32传感器采集与PYNQ编码器方案

2026-10-13，根据用户确认调整。最终再次确认：编码器保留PCB→PYNQ，超声波、红外接STM32。编码器已经完整接好，保留编码器PCB及JB1～JB4、JA9接线；超声波和红外恢复由STM32采集。该方案取代15号文档的新增传感器转换板建议，无需新增那块板。

采集源码直接从现有 `stm32预备程序/Source/APP/safe_car.c` 移植：保留TIM2微秒计时、EXTI12双边沿测宽、12us Trig脉冲、30ms等待上限和60ms触发间隔。`bsp_iravoid.h`、`bsp_ultrasonic.h` 原字节复制至对接版BSP，保留原厂版权，采集及初始化直接引用这些宏。新增修改用于真实采样序号、无效脉宽清零、红外稳定判断、串口校验和PYNQ接入。原厂 `bsp_getUltrasonicDistance()` 有等待Echo上升的无界循环，故沿用项目已有的非阻塞安全版实现，不将该阻塞函数接入控制轮询。未改变原电机PWM和制动实现。

## 硬件分工与接线

- 双前轮编码器：继续经现有SN74LVC245A PCB进入PYNQ PL；测速、里程、标定、原始非法跳变诊断均保留。
- 超声波：恢复原底盘J17四芯连接，VCC/GND按原板，Trig=STM32 PA15，Echo=PA12。PYNQ JB7/JB8不接该传感器，不在两块处理器之间并接信号。
- 左右红外：恢复原底盘红外模块连接；红外VCC使用经测量确认的3.3V/MVCC，OUT1高电平不得为5V。STM32 PA4、PA6在ST数据手册中不是FT引脚，不耐受5V；不能照搬此前新增LVC245板的红外5V供电建议。底盘原理图红外供电为MVCC、超声波为VCC，两者不是同一个网络；不盲改J16跳线。固件沿用原BSP定义PA6为左、PA4为右，读取避障OUT1而不是寻光OUT2。旧原理图左右标签有冲突，按实物分别遮挡核验；若相反，修改明确的左右映射后重新构建，不能把寻光位当避障位。PYNQ JA1/JA2不接红外。
- 板间UART：**JB9 TX→K1.3（经S5接通2–3后到STM32 PA3/RX）；JB10 RX←K1.4（STM32 PA2/TX）**；公共地接K1.2。K1.1不接，蓝牙模块拔下。2026-10-14按原理图信号网络勘误：原表将K1.3/.4写反，现已修正；S5是该输入路径的选择开关，不能将其与电池总开关S2混淆。详见17号UART勘误文档。
- 原编码器5V与底盘超声波5V不并联；底盘传感器电源实际电压、实物修订版和Echo输入条件仍须测量。PA12使用数字浮空输入，不开启USB外设或内部上下拉；不能泛化为任意STM32脚都耐受5V。电气依据：[ST STM32F103x8/B数据手册，Table 5](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf)。
- 电机动力仍接TB6612；当前包为LAB_ONLY，台架时保持动力物理断开。

## 同版软件与交付

FPGA契约升级为v0.10，ID `0xC425100A`。须使用新bit/HWH、新PYNQ运行软件和新STM32固件；旧v0.9包不支持串口传感器注入。当前权威源码目录不变，旧候选包只作追溯，不覆盖。

STM32固件：`stm32_pynq对接版/build_safe/safe_car.hex`（也生成BIN/ELF）。新部署包包含 `stm32_hybrid_v3.hex/bin/elf`，由完整流水线重编译并绑定哈希。

串口双方统一为 **115200、8N1**。原9600配置不能混用。新固件不接受旧 `$P` 驾驶帧、旧无校验 `$PREL#` 或USB `$ARM#` 解锁；保留无条件安全停止 `$PSTOP#`。

## UART v3

CRC采用CRC-16/CCITT-FALSE，初值FFFF，多项式1021，覆盖帧开头 `$` 到最后数据字段，不含CRC前逗号；四位大写十六进制。测试向量 `123456789→29B1`。

| 方向 | 帧 | 含义 |
|---|---|---|
| PS→STM32 | `$Q1,session,request,CRC#` | 查询，不刷新驾驶租约；随机32位非零session，32位递增request |
| STM32→PS | `$S1,session,request,us_seq,us_age_ms,us_valid,mm,ir_seq,ir_age_ms,ir_valid,ir,left,right,lock,fault,drop,CRC#` | 同批本地传感器及实际执行器反馈，回显查询身份 |
| PS→STM32 | `$D1,session,command_seq,left,right,CRC#` | 仅驾驶量；不能覆盖STM32本地测距、红外或采样时间 |
| PS→STM32 | `$R1,session,command_seq,CRC#` | 显式释放，仅在本地安全条件持续300ms后接受，不携带旧运动 |

本地超声波间隔至少60ms，等待Echo最长30ms，仅Trig脉冲等待约12微秒，不阻塞等待回波。真实测量成功/失败均推进US序号；回传、查询、驾驶不推进测量序号。红外每毫秒观察，连续三次一致更新状态，独立观察序号与时间；主循环停顿后重新建立稳定状态。

每个S1必须匹配当前session的一次尚未消费的Q1，查询发送到接收不超过150ms。重复、乱序、跨session及采样序号回退拒绝；STM32复位后若序号回退须重启当前会话，不自动恢复运动。32位序号按半模窗口识别真实回绕。

PS用 `查询发送时刻−报告样本年龄−2ms量化余量` 作为采样时刻保守下界，避免把串口接收时刻当真实采样时刻。相同采样序号保留最早时间，不被重复查询刷新。US最多200ms，IR观察最多100ms；查询超时或校验失败不会延长旧样本。

STM32独立使用本地真实US时间检查200ms采样过期、250ms驾驶租约、红外锁存、近障回差、启动锁和看门狗。数据在本地持续更新也不能延长已停止的驾驶源；查询不能延长驾驶租约。USB只用于停止、诊断和交还控制。

## PL数据入口

新增 `0x300～0x33F` 外部传感器寄存器。运行器先选择 `EXT_SENSOR_MODE=1`，再由唯一MMIO所有者锁存64位PL时钟，随后读取主机时间计算样本年龄；写入八个暂存字段（PL时钟锚点LO/HI、US数据/年龄/META、IR状态/年龄/META），最后写递增事务编号提交。锚点为PL时钟，不将PS绝对时间直接写入PL。

PL检查全字段写入、完整WSTRB和新事务编号，原子提交US与IR到现有公共时基、快照、风险流水和OSD。提交时用64位“当前PL时钟−锚点＋样本年龄”复检新鲜度，数据时间戳仍为“锚点−样本年龄”；主机暂停、MMIO延迟乃至32位时间回绕都不能把旧样本刷新。未来锚点撤销有效性。相同US/IR采样序号不更新时间，过期有效位保持撤销。缺字段、部分写、重复事务或非法格式撤销有效性。US和IR年龄分别处理，静止编码器的观察/里程语义保持原样。

原直接接PL的传感器模块保留供独立验证使用；正常整车运行选择STM32源，禁用PL超声波触发。视频只读显示，无权刷新控制样本。旧 `$CAR` 回显不能作为新的传感器或执行器证据。
