# 东南大学第二十届 PLD 设计竞赛报名撰写稿

## 项目名称

基于 PYNQ-Z2 的多传感器融合与动态风险感知 AR 辅助驾驶小车

## 拟选择赛题

题目二：面向自动驾驶小车的智能感知与先进显示系统设计

方向三：多传感器采集在环与 AR/VR 特色显示

## 赛题理解

本方向要求围绕智能车场景，在 FPGA 平台上实现至少两类传感器的实时采集、同步处理与信息融合，并将车辆运行状态、环境感知结果和风险判断叠加到视频画面或状态界面中，形成从传感器输入、实时处理、状态判断到显示输出的完整数据链路。

本项目计划以 PYNQ-Z2 为核心平台，以 STM32 作为小车底盘控制与执行平台，搭建一辆具备环境感知、运动状态测量和动态风险预警能力的智能小车。基础版本采用摄像头、轮式编码器和超声波传感器，分别获取前方环境画面、车辆速度与行驶里程以及障碍物距离。系统稳定后，再加入 IMU，用于测量车身姿态和角速度，并与编码器数据融合估计车辆的运动状态。

系统采用 PS 与 PL 协同架构。PS 端负责 USB 摄像头采集、图像帧缓存、参数配置、数据记录和 Jupyter 可视化；FPGA 的 PL 端负责编码器测速、超声波测距、统一计时、风险状态判断和视频 AR 信息叠加，并向 STM32 输出低速减速或停车控制指令。FPGA 计数器提供统一时间基准，PS 为视频帧记录时间戳，系统根据帧编号和传感器采样时间完成数据关联。

最终在实时视频中显示小车速度、行驶里程、障碍物距离、风险等级和车辆状态，并在低速实验条件下根据车速与障碍物距离触发减速或停车指令。

## 项目实施方案

系统以 PYNQ-Z2 为核心，按照 PS 负责管理、PL 负责实时处理、STM32 负责底盘执行的方式进行设计。

PS 端负责 USB 摄像头驱动、图像缓存、AXI 数据传输、参数设置、运行日志和 Jupyter 显示；PL 端负责编码器脉冲计数与测速、超声波 Echo 脉宽测量、传感器时间戳记录、风险等级计算和视频 OSD 叠加；STM32 接收 PYNQ-Z2 输出的控制指令，负责电机 PWM、底盘运动和执行机构控制。

项目基础版本拟实现：

1. 摄像头、编码器和超声波传感器的实时采集；
2. FPGA 计数器与视频帧编号相结合的时间关联机制；
3. FPGA 端编码器测速和行驶里程计算；
4. FPGA 端超声波测距；
5. 根据车辆速度和障碍物距离计算绿、黄、红三级风险等级；
6. 在视频画面中叠加速度、距离、方向和预警图标，并向 STM32 输出减速或停车指令；
7. 记录系统帧率、端到端延迟、传感器时间偏差和 FPGA 资源占用。

在基础版本稳定后，根据平台资源和开发进度增加 IMU 姿态检测、编码器与 IMU 融合定位、行驶轨迹回放以及基于图像边缘的道路区域识别功能。

电脑作为上位机，主要负责视频与传感器状态显示、参数配置、运行日志和轨迹回放。PYNQ-Z2 通过以太网接入无线局域网，电脑通过 WLAN 接收车辆状态并发送测试指令；WLAN 仅用于监控、遥控和低码率数据传输，不依赖无线链路完成核心风险判断和停车控制。PYNQ-Z2 与 STM32 之间保留本地控制链路，并设置通信心跳和超时停车机制，确保上位机或无线网络中断时小车能够进入安全状态。

小车的手动驾驶优先采用独立的 2.4 GHz 遥控器，由 STM32 直接接收遥控指令并控制电机；电脑 WLAN 指令用于上位机测试和参数调整。摄像头画面经 PYNQ-Z2 进行速度、距离、风险等级和预警图标叠加后，优先通过 HDMI 输出至场边显示器，作为比赛展示和调试时的主 AR 画面；电脑端可通过 WLAN 显示状态数据，并可选接收低码率压缩视频。遥控、AR 显示和风险停车相互独立，危险状态下由 PYNQ-Z2 或 STM32 优先执行减速和停车。

## 设计特色与创新点

第一，建立跨传感器和视频帧的统一时间关联机制，对摄像头、编码器和超声波数据进行时间配对，并通过实测时间偏差评价同步效果。

第二，根据车辆速度和障碍物距离动态计算风险等级。系统不只使用固定距离阈值，还考虑车辆当前速度和制动反应时间，构造动态安全距离：

`安全距离 = 安全余量 + 车速 × 反应时间 + 车速² ÷（2 × 最大减速度）`

这样能够在低速实验条件下实现比固定阈值更合理的分级预警。

第三，设计可解释的 AR 辅助显示界面，将速度、障碍物距离、车辆方向、风险等级和触发原因同时显示在视频画面中，使系统的感知结果和预警决策能够被直观理解。

第四，采用 PYNQ-Z2 与 STM32 分层协同的模块化设计，将 FPGA 实时感知处理与 STM32 底盘控制解耦。测速、测距、时间关联、风险融合、视频叠加和电机控制模块均可独立测试与替换，便于逐步扩展 IMU、车道检测和无线传输等功能。

## 项目可行性与验证计划

项目采用“软件参考模型—RTL 仿真—单模块上板—系统集成”的开发流程。前期先独立验证编码器测速、超声波测距、PWM 和视频显示模块；中期完成统一时间戳、风险判断和 AR 叠加；后期再进行小车底盘集成、低速减速停车、连续运行和异常情况测试。

基础版本的目标是实现 640×480 以上视频输入、稳定的实时状态显示、可重复的风险预警和连续运行测试，并提交完整的工程文件、设计文档、性能数据和演示视频。IMU、轨迹回放和道路区域识别作为基础系统完成后的拓展内容，不影响基础作品的独立交付。
