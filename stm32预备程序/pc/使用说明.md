# USB 小车控制台

本版本始终读取左右红外传感器（PA6、PA4，低电平为检测到障碍）。界面分别显示“左红外”和“右红外”，任一侧检测到障碍都会锁车。USB 首次接管会丢弃尚未处理的蓝牙数据并保持人工锁定，但不会被记录为“报文错误”。

桌面双击“STM32小车控制台”启动。依赖当前电脑 Python 3.14、Tkinter、pyserial。

连接：电脑 USB 数据线接扩展板板载 CH340 的 Micro-USB 口；不要接核心板 USB 口。串口自动优先选择 CH340，可手动刷新选择，115200/8N1。DAP 左侧 SWD 只用于烧录，不是这个上位机的控制线。主板需要合适的独立供电。

必须烧录此次更新的 build_safe/safe_car.hex，旧固件只发送串口状态，不接收 USB 驾驶。烧录后 BOOT0=0，复位运行。首次测试轮子悬空。

连接后等待状态，红外无遮挡、超声波有效距离至少250mm持续300ms，再点击人工解锁。可以按住界面的方向按钮，也可以按住键盘 `↑`、`↓`、`←`、`→` 控制；松开按键或移出按钮立即停止。超声波距离不大于200mm时仅禁止前进，后退和转向仍可用于脱离障碍；通信超时、测距无效和红外故障仍会锁车。空格、紧急停车、关闭窗口或失焦锁定。每100ms发送一次指令，板端500ms无有效USB帧会锁车，界面800ms无更新状态也会锁车。

USB 首次接收会取得控制权，蓝牙驾驶随即暂停。需要改用手机蓝牙时，在控制台点击“切回蓝牙（锁车）”：固件清除 USB 残留、锁车并重新接收 USART2；控制台会自动断开。也可以在未打开控制台的情况下复位 STM32，随后直接使用蓝牙。切换后必须先由手机发送停止帧，且传感器安全条件满足，才能解锁。

USB帧：`$HALT#`锁车；`$IDLE#`停止/心跳但不解锁；`$ARM#`请求人工解锁；`$BT#`安全切回蓝牙；方向沿用原十字段帧。返回原SAFE字段并增加USB0/1。文本协议无CRC，当前用于短线低速台架验证。USB状态采用严格格式校验及时间新鲜度检查。

本软件测试不能替代实车电气、蓝牙兼容性、停车距离和拔线测试。源码在同目录car_console.py。
# 2026-09-18通信接口验收补充

当前pynq_link.py已补独立来源API：新的驾驶意图调用update_command(left,right)，新的传感器样本调用update_sample(valid,mm,ir,sample_ts)。sample_ts必须映射到主机monotonic时基，不能把读取缓存的现在时刻当成采样时刻。drive仍保留给同一次调用确有新驾驶意图和同步样本的兼容场景。

接收端同时维护`state_seq`和`state_rx_time`：每个新解析成功的`$CAR`都会递增序号并记录本地单调时刻。台架验收必须用该序号区分STOP请求后的新状态与请求前缓存，不能仅凭`state`字段内容相同就认定收到响应。

采样过期、未来/非有限时间、请求过期均进入抑制。恢复后可发送带真实有效样本的零速帧；release_request仅请求解锁，不会重放缓存运动，之后必须提交新的驾驶请求。STM32仍需满足自身连续300ms安全条件；不能靠一次早到的PREL绕过。

当前18项主机测试通过。100ms发送节拍、串口传输和接收阻塞仍应纳入端到端停止时限模型；本模块单测不证明实车停车时延。详见项目根目录pynq_fpga/nightly/acceptance_20260918/任务1-4验收与修改报告.md。
