# 最小串口诊断固件

`build_minimal_uart_test.ps1` 会生成 `build_minimal_uart_test/minimal_uart_test.hex`。

这个版本不会启动电机 PWM、舵机、红外、超声波或蓝牙，也不会解析上位机行驶指令。四个电机方向脚被固定到停止电平，USART1 只以 115200/8N1 发送 `$MINI,OK,STOP#` 心跳，并在 RAM 中累计接收字节数和硬件错误数。

## 使用顺序

1. 电池、底盘 USB 和其他串口线先拔掉，只保留 DAP 的 SWD：GND、DIO、CLK；DAP 的 3V3 只在确认供电方式后使用。
2. 用 DAP 烧录 `build_minimal_uart_test/minimal_uart_test.hex`，烧录完成后复位运行。
3. 如需观察心跳，再接底盘 Micro-USB；不要接 DAP 右侧 TX/RX。
4. 测试时车轮保持悬空，仍不要点击上位机的方向按钮。

程序中的 `mini_error_count` 是 USART1 的 ORE/FE/NE/PE 总数；它不是上位机解析错误。若最小程序仍持续增长，问题优先指向 PA9/PA10、CH340 或底板电气连接；若保持为 0，再回到原程序检查外设初始化和发送路径。

## 本次测试结果（2026-09-09）

- 最小固件烧录和校验成功，DAP 识别为 STM32F103C8T6，写入 1008 字节。
- 仅开启 USART1 发送固定心跳、关闭其他外设运行约 3 秒：发送 6 次，`mini_error_count=150`，正常接收 0 次。
- 在同一固件中临时关闭 USART1 发送器运行约 3 秒：错误计数保持 0。
- 暂停后把 PA9 改为推挽输出低电平，PA10 仍读到高电平（GPIOA IDR 的 PA10 位为 1）。因此目前不能把现象定性为 PA9 与 PA10 的直流硬短路；更像是 PA9 发送波形经底板/CH340 接口产生了串扰、错误连线或负载影响。
- 将核心板从底板拔下、只接 DAP 的 SWD 和 3.3 V 后重新测试约 3 秒：发送 6 次、`mini_error_count=0`、正常接收 0 次。由此确认核心板 USART1 本身正常，错误来自核心板插回底板后出现的底板/CH340 串口路径问题。

测试结束时 CPU 由 DAP 保持暂停，电机没有运行。恢复原小车功能前，需要重新烧录 `build_safe/safe_car.hex`；在硬件串口问题解决前，不建议解锁行驶。
